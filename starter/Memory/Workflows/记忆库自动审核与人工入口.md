# 记忆库自动审核与人工入口

> 本工作流只在 Inbox 审核或季度复核时读取，不占 Agent 启动上下文。

## 自动审核

每天审核「登记日期早于运行当天」的 Inbox 日记账：格式合规、落库项存在性分级核对、重复/冲突抽查、决策格式门检。整份通过才勾选「待审核」并移入 `Inbox/Archive/`。

### 审核范围

- 对象：`Inbox/` 根下文件名形如 `YYYY-MM-DD.md` 的登记文件，且**登记日期早于运行当天**。
- 不审：`Inbox/Archive/` 留档、`drafts/`、子目录、当天及以后新增、不含合法日期名的文件。
- 任务停机后恢复时，窗口会自动覆盖多份积压，属预期；照常审并在结论里报出份数。
- 本任务只移动、不删除；任何删除、合并、改写用户手写内容的动作都不做。

### 逐条核对

1. **登记格式**：判据 = `rule/写入与禁止.md`「写入」第 4 条。重点：每天一个文件、追加块、`软件` 在正文不在 frontmatter、禁止抄正文、不追改旧块。
2. **落库项存在性**，分三级、不混判：
   - 记忆库内 `.md` 路径：全量核对在位。这是本任务最值钱的产出——「该落的没落」要能被发现。
   - `scripts/_out/` 一次性脚本与报告：只核所在目录存在；个别文件缺失不立案（本就会被清理）。
   - 库外与派生物（git commit / HEAD、代码工作树、工具配置位、站点构建产物）：一律标「未核」，不判红；要核也得先确认对应仓与主机，成本高于收益。
3. **重复/冲突**：抽查，必要时用 `memory_query.py` 按关键词检索；发现实质矛盾不改原文，转入待裁。
4. **决策格式门检**：仅对审核窗口内新增的 `Decisions/` 笔记生效，存量不溯及。新增集 = 各块「落库位置」点名的新笔记 ∪ `Decisions/` 中 `created` 落在窗口内的文件。缺失 `status` 或「备选方案」节属实质问题，**只报告不代改**——审核方不得替他人补字段或塞逃生注释，那是人的判断。

### 处理方式

- **以文件为单位**：某份日记账的**全部**块都过、且块内不留未结「待本人决定」→ 把各 `- [ ] 待审核` 勾为 `- [x]` 并整份移入 `Inbox/Archive/`（保留日期名）。任一块未过 → 整份不勾、不移、不动。
- **纯格式问题**（缺 frontmatter / 缺待审核行）可直接补齐：只加行不改正文，保持 UTF-8 无 BOM。
- **实质问题**（库内落库文件确实缺失、内容矛盾、决策缺 `status` 或备选节）及涉及删除、合并、改写用户手写内容的：不归档、不动；按需写入 `Todo.md` 中本工作流所属项目的分组。**首次挂账前先建齐落点**：`Projects/记忆库/_overview.md`、`Projects/记忆库/working/completed/` 季度分片、`Todo.md` 的 `## 记忆库` 分组——三者缺一，待办归档门禁会报「分组无对应项目目录」。写前两步核对：
  1. grep 该组与相关 journal【候选】是否已在册；
  2. 查该悬项是否已被更晚的 Inbox 块或 journal 落注解决——已解决就不挂账，结论只写进当日 journal，**不回改旧登记块**。
- 上次运行留下「已勾 `[x]` 但仍在 Inbox 根」的块 = 移动被拦或中断 → 只补移动，不重审。
- 记忆只落 `Memory/`，绝不写入 `.workbuddy/memory/`、`.memory/` 等任何工具私有位。

### 产出

- 审核结论作为**当日** `Inbox/YYYY-MM-DD.md` 的一个登记块追加（无当日文件则按 `Templates/Memory-Inbox-Note.md` 新建）。`软件` 标实际执行本任务的工具名；`落库位置` 写本轮真实写入/移动的文件清单；保留 `- [ ] 待审核` 由次日审。正文只写计数与指路，不抄正文。
- 同一天已存在本任务的审核块 → 更新该块，不重复追加。
- 摘要写入本工作流所属项目（建议 `Projects/记忆库/`，没有则先建档）的 `working/journal/YYYY-MM.md` 当日小节；结案事项记同目录 `completed/YYYY-QX.md`。
- 收尾门禁本任务自己跑一遍，把退出码与报告路径写进 journal 当日小节，不依赖外部 Stop hook。
- 若 Inbox 无早于当天的条目：只回一句「无需审核」，不建不改。

## 人工入口

- 定期看 `Inbox/Archive/` 的结案记录、`Todo.md` 中本工作流所属项目的挂起项、以及审核结论中的「待本人决定」。
- 对自动化结论有异议 → 直接改目标文件，并在当日登记中备注。
- 人工可以否决自动化结论；自动化不得改用户手写内容。

## 停跑可见性

审核任务可能因设备关机、节假日、应用未运行而跳过且不补跑。`todo_audit.py` 的「每日 Inbox 审核积压」报告段会列出 `Inbox/` 根下早于运行当天的登记文件——**只报不拦**：积压可能来自任务没跑，也可能来自「审过但块里留有『待本人决定』」。季度只看积压份数是否归零与最长滞留天数趋势。

## 步骤 → 验证

| 步骤 | 验证：可观测成功信号 |
|---|---|
| 1 取窗口 | 份数 = `Inbox/` 根下满足「日期名 + 早于运行当天」的文件数；无满足项时只回「无需审核」，且 `Inbox/` 根与 journal 字节数不变 |
| 2 存在性三级核对 | 登记块三个计数齐备（库内 `.md` 在位数 / `_out/` 目录在否 / 未核项数）；「未核」项不出现在实质问题列表 |
| 3 决策门检 | 本轮 `Decisions/*.md` 零写入；缺 `status` 或缺备选节的进入待裁指针 |
| 4 整份归档 | `Inbox/Archive/YYYY-MM-DD.md` 的 mtime 落在本轮窗口内、`Inbox/` 根不再含同名文件；根内不存在「已勾 `[x]` 仍在根」的块 |
| 5 审核方自登记块 | 当日 `Inbox/YYYY-MM-DD.md` 新增块含 `软件`=实际执行工具名、`落库位置`=本轮真实写入/移动清单、保留 `- [ ] 待审核` |
| 6 journal + 门禁 | journal 当日节写了退出码与报告路径；`todo_audit.py --check` 复跑通过 |
| 7 待裁入 Todo | 新条在本工作流所属项目分组与相关 journal【候选】grep 零命中；已被更晚登记解决的只落 journal、不回改旧登记块 |
| 8 写入面一致 | 本工作流不需要派生索引；`落库位置` 与实际写入清单逐项一致 |
