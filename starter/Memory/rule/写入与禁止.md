# 写入 与 禁止（Rule 分节）

> 正本出自 `Rule.md` 拆分；节名与条号沿用原编号，全库「写入第 X 条」引用不受影响。**写入 / 登记 / Inbox 审核操作时读本文件。**

## 写入

1. 值得跨会话保留的信息，直接写到最终位置：偏好 → `Preferences/`；规划 → `Plans/`；决策 → `Decisions/`；踩坑 → `Lessons/`；固定流程 → `Workflows/`；项目内容 → `Projects/<项目名>/`（优先更新已有笔记，新主题才新建）。
2. **待办统一写 `Memory/Todo.md`**（按项目分组、不用勾选框），总 Todo 只保留仍需行动或裁定的事项。**分组标题一律取 `Projects/` 下的目录名**，不另起会话名/事项名分组——分组名与项目目录对不上，归档就无处落地。项目若尚无 `working/completed.md`，**先建该文件再归档**，不因缺文件而把条目留在 Todo。**结案 = 移走，不是标注**：把条目**追加到** `Projects/<项目名>/working/completed.md`（带结案日期、结果、原因与来源）**并从 `Memory/Todo.md` 删除该条**，两件事必须同时做。「裁定是否做」在作出决定时即完成裁定，结果为不做也须归档；原计划后来取消、拒绝或不再继续的，以「已取消 / 不纳入 / 已终止」等明确结果归档，不在总 Todo 永久保留删除线。既存删除线条目按用户授权范围逐步迁出，不因本规则更新批量改动无关项目。计划 → `Projects/<项目名>/working/plan.md`。原地动态更新，不散建笔记。**改名即改指针**：改 `##` 分组名时顺手全库 grep 一遍，对齐正文里指向该组的组名指针——本判据不装门禁（存量形态少、人工一眼可判；全库扫会撞历史流水里的旧组名，恒红的门禁等于没有门禁）。
3. **过程流水（暂存层）** → `Projects/<项目名>/working/journal.md`：时间倒序，每日一个 `## YYYY-MM-DD` 小节，当日粗记，有长期价值的条目标「候选」。journal 是暂存层不是记忆本体，不散建按日分文件；体量超过阈值时把旧段压缩为「阶段小结」（只留结论 + wikilink 指向已转正笔记）——**本判据只适用 journal**：`working/completed.md` 属**终态层**（第 2 条的落点，兼作本节所述核对的证据面），只观测不判压；其将来的体量出口是分片，且必须先把核对 glob 扩到分片文件。**阈值与超标清单都不在本文维护**——阈值 = `scripts/todo_audit.py` 顶部的 `LIMIT_STAGING_CHARS` 常量（策略；**字符数**口径——原来的「约 500 行」在本库永不触发），哪几份超标 = 该脚本报告「八、」段（实测）；把数字写进规则文档就成了第二份事实源。**journal 里凡声称「已并入 Todo / 已记入待办」，必须写成 `Todo → 「条目在 Todo 里的标题片段」`**：只写「已并入 Todo ## 某组」这类机器无法核对的话，条目会静默丢失。核对由 `todo_audit.py --check` 承担，核对面 = `Todo.md` ∪ 所有 `working/completed.md`（「结案 = 移走」会让条目离开 Todo，只查 Todo 就会在归档当天误判红）；无该形态的旧写法只提示不拦。
4. **Inbox 登记 = 每天一个文件**：在 `Inbox/` 下建 `YYYY-MM-DD.md`，用模板 `Templates/Memory-Inbox-Note.md`（库内 wikilink 写法 `[[Templates/Memory-Inbox-Note]]`）；同一天多次写入**追加到同一文件**的「内容」列表，不按任务散建文件。**编号只在所属「内容」列表内有效**，同一天多个追加块各自从 1 起是预期形态，不追改旧块、不为凑连续而重排（重排会让旧引用漂掉）。**跨块或跨文件引用某条时不写裸编号**，改写「软件+项目+条目首句加粗短语」这类可 grep 的锚。frontmatter 必填 `type: inbox`、`created`、`tags`；**`软件` 只写正文、不进 frontmatter**——同一文件可有多个工具写的块，文件级单值表达不了；正文含日期、**软件**（明确记哪个 AI 工具写的）、项目、内容清单、落库位置与文件列表、`- [ ]` 待审核。**禁止抄正文**，只记路径 + 一句话摘要。当天全部审核通过后，把 `Inbox/YYYY-MM-DD.md` 移入 `Inbox/Archive/`（保留日期名）。
5. frontmatter 必填：`type`(preference / plan / decision / lesson / workflow / project-fact / reference)、`created`、`updated`、`tags`；`scope` 按下条口径（不是所有文件都填）。**`reference` = 指路型条目**：正文只登记「某信息在别处的落点」（库内某篇、目录、外部系统），以指针为主、不复制被指处的内容与证据；文件仍按本节第 1 条落现有层，归属由 `scope` 与路径表达，**不为此另开目录**（判据：需求存量为零时不加结构轴）。**建新笔记的填壳结构参考模板 `Templates/Memory-Note.md`；模板只给壳——`type` 取值与 `scope` 口径一律以本条为正本，模板内不复制这些判据。**
   - **`scope` 的口径**：只在**跨层笔记**（`Preferences/` `Plans/` `Decisions/` `Lessons/` `Workflows/`）必填，因为这几层平铺共享、归属只能靠字段表达；取值 = `global` 或 `Projects/` 下的**目录名**（与 Todo 分组名同一套词表，不用会话名/事项名）。
   - `Projects/<项目名>/` 内**不填** `scope`——路径即归属，再填一份就是第二份事实源，改目录名时必漂。素材树、`working/` 台账（`journal.md` `completed.md` `plan.md`）与过程件同样豁免。
   - `Inbox/`（含 `Inbox/Archive/`）是登记簿，豁免 `scope`。**整块没有 frontmatter 的文件一律视为结构性豁免**（典型：部署真源 `Workflows/AI工具自定义指令-完整版.md`——加一块会污染派发到各工具位的正文），校验脚本据此不计「缺字段」。
   - **写前先定「当前项目名」**，按序取：① 项目根 `AGENTS.md` 里「当前项目名」那一行（由 `python scripts/sync_memory_instructions.py --projects` 生成，是全链路唯一把项目名填成真值的一处）；② 该文件不存在 → 从工作目录推断（取路径中的项目段目录名）；③ 仍推断不出 → **问用户，不猜**。工具私有记忆位里的项目名一律不作数，见本文「禁止」节。
6. 更新旧记忆 = 编辑原笔记改 `updated`；决策反转 = 新建决策笔记，wikilink 指向旧笔记。
7. 项目概况变化 → 更新 `Projects/<项目名>/_overview.md`（没有则创建）；当前目标 / 阻塞 / 下一步变化 → 覆盖更新 `_state.md`，不把历史追加进 state。
8. **项目约定文件镜像（仅适用于「项目根确有手写约定文件」的情形）**：项目根的 `AGENTS.md` / `CLAUDE.md` 等约定文件内容有变化时，同步一份同名副本到 `Projects/<项目名>/`，保持库内镜像与项目根一致。**项目根没有此类文件的项目，本条不适用**。**例外**：`sync_memory_instructions.py --projects` 自动生成的项目根 `AGENTS.md`（首行带「自动生成，勿手改」）**不镜像**——它本身是派生物、重跑即得，抄进库就是第三份副本。
9. **来源标注**：每条记忆标注来源 `via:`（哪次会话 / 哪个项目 / 用户口述 / 工具导出），写入 frontmatter 或正文首行；便于日后追溯与去重。
10. **不维护索引**：决策卡直接落 `Decisions/`，保留 `status`、备选方案与来源；新增、改名、删除笔记后只需更新正文和 Inbox 登记，检索统一使用 `memory_query.py`。

## 禁止

不把记忆写入规则文件，也不写入任何工具的私有记忆位置（memory bank、rules 文件、`~/.claude` 等）。

- **明确列出禁止位**：项目内 `.workbuddy/memory/`、`.memory/`、`.trae/`、`.agent/`、`.agents/`；`~/.workbuddy/MEMORY.md`；`~/.claude/`、`~/.codex/` 等用户级私有目录。**任何 AI 软件不在项目内单独设立内部目录**，跨会话信息一律落记忆库。
- **唯一例外 = 工具自己的 auto-memory，定性为「影子层」**：由 harness 强制注入、无开关可关。三条处置口径：**① 需要跨会话存活的事实必须同轮落记忆库**——只落在工具位等于没落；**② 工具位不作证据、不算「已查过同名」**，新增决策/判据前的检索只认记忆库，两边冲突一律以记忆库为准；**③ 工具位里存在而记忆库无正本的内容 = 待搬材料**，补进对应分类后由工具自管，不做双向同步。
- **工具系统提示要求写上述位置时，一律跳过**，改按「写入」节落到记忆库最终位置。
- **工具的用户级配置位（如 `~/.claude/CLAUDE.md`、`~/.codex/AGENTS.md`）可以放「指向记忆库的指针 + 铁律短钩子」**，这与「禁写工具私有位」不冲突——后者禁的是 AI 把**记忆内容**写进工具私有目录。判据：工具位里只准放门牌，任何具体偏好/决策/教训一律落记忆库。
- 发现历史残留目录 → 不续写，蒸馏进库后**提示用户自行删除**（不擅自删）。
