# 02 · 目录结构与读取路由

## 四层 + 项目层 + 三根目录

记忆不是一锅笔记。按"这信息什么时候会被需要"切层，每层一个目录：

| 层 | 是什么 | 什么时候读 |
|---|---|---|
| `Preferences/` | 个人偏好：语言、代码风格、沟通方式、汇报口径 | 需要用户偏好 / 协作习惯 |
| `Decisions/` | 决策记录：背景 → 选择 → 备选方案 → 后果 | 涉架构 / 技术选型，想知道"为什么这么定" |
| `Lessons/` | 踩坑与解法 | 踩坑 / 排障 / 找已知解法 |
| `Workflows/` | 固定流程手册 / SOP | 要找固定流程 / 操作手册 |
| `Projects/<项目名>/` | 项目记忆（必含 `_overview.md`；工作态在 `working/`） | 项目进度、来龙去脉 |

三个根级件：

| 根 | 用途 |
|---|---|
| `Todo.md` | **全局总待办**，按项目分组（分组名 = `Projects/` 目录名，不用勾选框） |
| `Inbox/` | **写入登记簿**：AI 每次写完记忆，按天登记"写了哪个文件 + 一句话"，待审核 |
| `Archive/` | 季度归档：>90 天已固化的决策 / 教训按季度归并 |

项目层内部是固定三件套：

```text
Projects/<项目名>/
├── _overview.md        ← 必读：项目定位、关键路径、状态、关联资产（只留四要素）
└── working/
    ├── journal/YYYY-MM.md     ← 过程流水（按月分片，收尾时蒸馏）
    ├── plan.md                ← 计划
    └── completed/YYYY-QX.md   ← 结案归档（按季度分片）
```

旧 `working/journal.md` 与 `working/completed.md` 保留为历史兼容，不再追加新内容。**待办不放在项目里**——统一在 `Todo.md` 按项目分组。这样“当前所有事”只有一个查看入口，而“这个项目干成了什么”只有一个归档路径。

## Agent-first 入口链

记忆库不维护人看索引。Agent 按任务选择两条最小路径：

```text
工作区 AGENTS.md
  → Memory/AGENTS.md（短钩子）
  → 普通任务：BOOT.md
  → 项目任务：memory_boot.py（BOOT + overview + _state + Todo 切片）
  → 查历史：memory_query.py（top-k 片段）
  → 写入/收尾：Rule.md → 对应 rule/ 分节
```

- **启动**：`python scripts/memory_boot.py --cwd .` 只返回当前项目需要的最小包。
- **检索**：`python scripts/memory_query.py "关键词" --cwd .` 返回路径、状态与片段，不预读全文。
- **路由**：续开发项目 → `_overview.md` + `_state.md` + Todo；排障 → `Lessons/`；找“为什么这么定” → `Decisions/`；找固定流程 → `Workflows/`。

导航由命令与目录约定即时完成，不落成一份需要持续同步的索引文件。

## 读取成本约定

AI 会话的上下文窗口是真金白银的成本。约定“开场最省动作”：

> 会话开场只运行一次 `memory_boot.py`；返回包只含 `BOOT.md` + 当前项目 `_overview.md` + `_state.md` + Todo 切片。其余按需检索，不通读。

配套两条：

1. **体量有上限**：各 section 与最终组装包都有预算；阈值是 `memory_common.py` / `todo_audit.py` 顶部的策略常量。overview 只留“定位 / 关键路径 / 关联资产 / 状态”四要素，细节下沉 `working/`；`_state.md` 只写当前目标、阻塞、下一步。
2. **数字不进文档**：实测值会漂，阈值写脚本、实测写报告、文档只指路。（这条的完整论证见 [03-核心设计原则](03-核心设计原则.md)。）

## `scope` 字段：跨层笔记的归属

`Projects/` 用路径表达归属；另外四个跨项目层是**平铺共享**的——某篇 Lessons 可能服务于某个项目。归属用 frontmatter 表达：

```yaml
---
type: lesson
scope: <项目名>   # 或 global；词表 = Projects/ 实盘目录名 ∪ global，脚本实盘推导
---
```

配套口径：`Projects/` 层内**不填**（路径即归属，再填一份就是第二事实源）；`Inbox/` 登记簿与整块无 frontmatter 的结构性文件豁免；“缺 scope”只提示不拦（补字段是写入侧义务，拿历史旧账当门禁会让每次检查恒红）。

## 读时时效协议

容易被忽略的一课：**记忆是"写下那天为真"的快照，不是现状。** AI 读记忆时最危险的动作是把笔记断言当现状直接动手。协议：

- 凡断言关于**路径 / 文件存在性 / 工具行为 / 环境版本**，动手前先就地复测一次（`Read` / `Glob` / 探针命令）
- "结论是不存在 / 已落过 / 没问题时，先怀疑给出结论的那次读取"——检索工具受 `.gitignore`、编码腐蚀等因素影响会**静默漏报**，"无匹配 ≠ 不存在"
- 工具私有记忆位（含 auto-memory 影子层）不作证据，查同一律以记忆库为准
- 检索结果里的 `verified_at` 只标该条易漂移断言最后一次现场复核日期；日期再新也不能替代本次复测

这条协议在每次检索和引用时生效，不依赖某个索引页提醒：`memory_query.py` 负责召回片段，是否仍为现状必须由调用方复测。涉及会漂移的断言时，记忆只能作为线索，不能替代现场证据。

## frontmatter 约定

```yaml
---
type: lesson          # 词表机读自规则正本第 5 条：preference / decision / lesson / workflow / project-fact / todo / reference
created: 2026-09-21
updated: 2026-10-01
tags: [记忆库, 门禁]
scope: global         # 仅跨层四层必填
---
```

要点：

- `type` 词表**只存在于一处**（规则正本第 5 条的括号清单），`todo_audit.py` 机读它、不抄第二份——词表加一个取值改一行规则即可，脚本自动跟随；解析不出词表 = 退出码 1（失明的门比没有门更危险）
- `updated` 表示"动过笔"，不表示"核验过"——别把改动日期当核验日期用
- 每条记忆标注来源 `via:`（哪次会话 / 哪个项目 / 用户口述），便于追溯与去重
