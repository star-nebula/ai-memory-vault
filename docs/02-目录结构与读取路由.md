# 02 · 目录结构与读取路由

## 六层 + 三根目录

记忆不是一锅笔记。按"这信息什么时候会被需要"切层，每层一个目录：

| 层 | 是什么 | 什么时候读 |
|---|---|---|
| `Preferences/` | 个人偏好：语言、代码风格、沟通方式、汇报口径 | 需要用户偏好 / 协作习惯 |
| `Plans/` | 长期规划、目标、路线图 | 需要长期规划与目标 |
| `Decisions/` | 决策记录：背景 → 选择 → 备选方案 → 后果 | 涉架构 / 技术选型，想知道"为什么这么定" |
| `Lessons/` | 踩坑与解法 | 踩坑 / 排障 / 找已知解法 |
| `Workflows/` | 固定流程手册 / SOP | 要找固定流程 / 操作手册 |
| `Projects/<项目名>/` | 项目记忆（必含 `_overview.md`；工作态在 `working/`） | 项目进度、来龙去脉 |

三个根级件：

| 根 | 用途 |
|---|---|
| `Todo.md` | **全局总待办**，按项目分组（分组名 = `Projects/` 目录名，不用勾选框） |
| `Inbox/` | **写入登记簿**：AI 每次写完记忆，按天登记"写了哪个文件 + 一句话"，待审核 |
| `Archive/` | 季度归档：>90 天已固化的决策 / 教训按季度归并 |

项目层内部是固定三件套：

```text
Projects/<项目名>/
├── _overview.md        ← 必读：项目定位、关键路径、状态、关联资产（只留四要素）
└── working/
    ├── journal.md      ← 过程流水（时间倒序，暂存层，收尾时蒸馏）
    ├── plan.md         ← 计划
    └── completed.md    ← 已完成（带日期）——待办"完成 = 移走"的落点
```

**待办不放在项目里**——统一在 `Todo.md` 按项目分组。这样"当前所有事"只有一个查看入口，而"这个项目干成了什么"只有一个归档入口。

## 唯一入口与分层路由

`Memory/_index.md` 是**唯一入口**。AI 进来的第一动作是读它，而不是猜文件在哪。它包含：

- **分层地图**：每层"是什么 / 什么时候读"
- **典型路由**：续开发某项目 → `Projects/<项目名>/_overview.md` + `Todo.md` 对应分组；排障 → `Lessons/`；找"为什么这么定" → `Decisions/`
- **逐篇索引**：每层一份 `_index.md`（由脚本生成，见下）
- **读取成本约定**与**读时时效协议**（见下文）

入口页只有"在哪 + 是什么 + 什么词能命中"，**不复制正文**——正文复制一份就是第二份事实源，必然漂移。

## 读取成本约定

AI 会话的上下文窗口是真金白银的成本。约定"开场最省动作"：

> 会话开场只读三件：`_index.md` + `Todo.md` + `Projects/<项目名>/_overview.md`。其余按路线下钻，不通读。

配套两条：

1. **体量有上限**：三件套各自的字符数阈值是脚本顶部的策略常量（`todo_audit.py` 的 `LIMIT_*`），超标文件进"待瘦身"清单——overview 只留"定位 / 关键路径 / 关联资产 / 状态"四要素，细节下沉 `working/`。
2. **数字不进文档**：实测值会漂，阈值写脚本、实测写报告、文档只指路。（这条的完整论证见 [03-核心设计原则](03-核心设计原则.md)。）

## `scope` 字段：跨层笔记的归属

六个层里，`Projects/` 用路径表达归属，但另外五层是**平铺共享**的——某篇 Lessons 可能服务于某个项目。归属用 frontmatter 表达：

```yaml
---
type: lesson
scope: <项目名>   # 或 global；词表 = Projects/ 实盘目录名 ∪ global，脚本实盘推导
---
```

配套口径：`Projects/` 层内**不填**（路径即归属，再填一份就是第二事实源）；索引文件与登记簿豁免；"缺 scope"只提示不拦（补字段是写入侧义务，拿历史旧账当门禁会让每次检查恒红）。

## 读时时效协议

容易被忽略的一课：**记忆是"写下那天为真"的快照，不是现状。** AI 读记忆时最危险的动作是把笔记断言当现状直接动手。协议：

- 凡断言关于**路径 / 文件存在性 / 工具行为 / 环境版本**，动手前先就地复测一次（`Read` / `Glob` / 探针命令）
- "结论是不存在 / 已落过 / 没问题时，先怀疑给出结论的那次读取"——检索工具受 `.gitignore`、编码腐蚀等因素影响会**静默漏报**，"无匹配 ≠ 不存在"
- 工具私有记忆位（含 auto-memory 影子层）不作证据，查同一律以记忆库为准

这条协议被做成了门禁：`mem_index.py --check` 校验 `_index.md` 里"读时时效"小节在场且判据指针未被抽走——**改名或删除即报红**。为什么落点在 `_index.md` 而不是规则文件？因为规则文件只在"写入 / 收尾"时被读，而这条约定在**每次读取**时都该生效——`_index.md` 在"先读索引再读原文"的路径上，读者必然经过。

## frontmatter 约定

```yaml
---
type: lesson          # 词表机读自规则正本第 5 条：preference / plan / decision / lesson / workflow / project-fact / reference
created: 2026-09-21
updated: 2026-10-01
tags: [记忆库, 门禁]
scope: global         # 仅跨层五层必填
---
```

要点：

- `type` 词表**只存在于一处**（规则正本第 5 条的括号清单），`todo_audit.py` 机读它、不抄第二份——词表加一个取值改一行规则即可，脚本自动跟随；解析不出词表 = 退出码 1（失明的门比没有门更危险）
- `updated` 表示"动过笔"，不表示"核验过"——别把改动日期当核验日期用
- 每条记忆标注来源 `via:`（哪次会话 / 哪个项目 / 用户口述），便于追溯与去重
