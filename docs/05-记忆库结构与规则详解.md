## 1. 一页总览

这套系统可以用一句话概括：

> **把一个纯 Markdown 目录作为 AI 的唯一记忆落点，用一份分层索引决定“读什么”，用四条规则决定“怎么写”，再用四个脚本把最容易漂移的环节变成门禁。**

它不是某个工具的插件，也不是一个数据库。把 `starter/` 与 `scripts/` 一起复制到工作区根目录，就算完成部署：

```text
AI 工具进入工作区
   │
   ├─ 根 AGENTS.md            工作区地图 + 记忆库门牌 + 同名文件消歧
   │
   └─ Memory/_index.md        唯一入口：分层地图 + 读取路由 + 成本约定
        │
        ├─ 读：按路由读原文（Preferences / Plans / Decisions / Lessons / Workflows / Projects）
        │
        ├─ 写：写到最终层；待办进 Todo.md；过程进 working/journal.md；
        │      每次写入在 Inbox/YYYY-MM-DD.md 登记
        │
        └─ 收尾：journal 蒸馏 → 更新 overview → 同步指令 → 跑门禁
```

### 1.1 四条主线

| 主线 | 触发时机 | 核心动作 | 落点 |
|---|---|---|---|
| **读** | 会话开场、需要背景、排障、找决策 | 读入口 → 读三件套 → 按路由下钻 → 复测时效 | `_index.md`、`Todo.md`、`Projects/<项目名>/_overview.md` |
| **写** | 产生跨会话有价值的信息 | 先分类 → 写最终位置 → 补 frontmatter → 登记 Inbox | 六个内容层 + `Todo.md` + `Inbox/` |
| **完成** | 待办做完 | 追加到 `completed.md` 并从 `Todo.md` 删除 | `Projects/<项目名>/working/completed.md` |
| **维护** | 会话收尾、每季度 | 四步收尾、五道门禁、归档蒸馏 | `Archive/`、`Inbox/Archive/`、各层索引 |

### 1.2 系统不变量

下面几条一旦被破坏，系统就会退化成“又一堆没人看的笔记”：

1. **唯一记忆落点**：跨会话信息只写 `Memory/`，不写任何工具私有记忆位。
2. **唯一入口**：AI 从 `Memory/_index.md` 进入，不从猜测的文件路径进入。
3. **索引是派生物**：除 `Decisions/` 外各层 `_index.md` 由脚本生成，人工只润色“一句话定位”；`Decisions/_index.md` 专用格式，手工维护。
4. **结案 = 移走**：Todo 里不保留完成标记，完成与取消都必须进入 `completed.md`。
5. **有门禁才不漂移**：靠“记得同步”的约定一律视为不可靠。
6. **读记忆不等于信记忆**：记忆是写下当天的快照，涉及路径、文件存在性、工具行为时先复测。
7. **用户手改的文件绝不自动改**：自动化只能报告，不能替用户改判断。

## 2. 设计目标与边界

### 2.1 它解决什么问题

| 问题 | 传统工具记忆 | 本系统的处理 |
|---|---|---|
| 跨工具失忆 | 每个工具有自己的 `memory/`、`AGENTS.md`、auto-memory | 所有工具共用一个 Markdown 目录 |
| 跨会话失忆 | 只保留上一轮摘要 | 分层笔记 + 项目台账 + 决策/教训 |
| 不可审阅 | 私有格式、藏在工具配置里 | 纯文本、可搜索、可 diff、可用 Obsidian 打开 |
| 记忆质量差 | 会话末尾匆忙摘要 | 写入有分类、有模板、有 Inbox 登记与审核 |
| 记忆漂移 | 手工索引、手工同步 | 索引脚本化、指令分发脚本化、门禁化 |

### 2.2 “门牌”与“货物”

系统对工具位划了一条非常清晰的边界：

- **工具位可以放**：指向记忆库的路径、铁律短钩子、读取顺序。
- **工具位不能放**：偏好、决策、教训、项目事实等任何**记忆内容**。

> **判据：工具位里只准放门牌，不准放货物。**

因此，`~/.claude/CLAUDE.md`、`~/.codex/AGENTS.md`、项目根 `AGENTS.md` 都可以存在，但它们的内容只能是“去 `Memory/` 读什么、怎么写”的指针，不能变成第二份记忆库。

### 2.3 auto-memory 的“影子层”定性

有些工具的 auto-memory 由 harness 强制写入，关不掉。系统没有假装能禁止它，而是给它一个明确定性：

> **影子层**——只当缓存看：不作落点、不作证据、不算“已查过同名”；需要跨会话存活的事实必须**同轮**落记忆库；影子层有而记忆库无正本的内容 = 待搬材料（单向搬入，不做双向同步）。

这条定性解决了三个现实问题：

1. 不必写一条“必须关掉 auto-memory”的做不到的铁律；
2. 工具位与记忆库冲突时，永远以记忆库为准；
3. 强制写入的内容不会被误当成“已经记过了”。

### 2.4 单一事实源

同一份事实只允许存在一处，其余位置要么是指针，要么是派生物：

- 索引：`_index.md` 由笔记 frontmatter 生成，不手写条目；
- 指令：各工具位的正文由 `Workflows/AI工具自定义指令-完整版.md` 派生；
- 词表：`type` 词表从规则正本机读，`scope` 词表从 `Projects/` 实盘目录名推导；
- 体量阈值：只存在于脚本常量，文档只指路，不抄数字；
- 决策：反转时新建笔记并互链，不覆盖旧笔记。

## 3. 两种结构：发布仓库 vs 运行中的记忆库

这是理解本项目时最容易混淆的一点。

### 3.1 这个仓库本身是“发行版”

`ai-memory-vault` 不是一份正在使用的记忆库，而是这套系统的**源码/发行仓库**：

```text
ai-memory-vault/
├── README.md               英文主说明
├── readme/                 多语言说明
├── docs/                   设计思路与事故复盘（01–04，本文为 05）
├── starter/                可整体拷走的记忆库骨架
├── scripts/                四个门禁/运维脚本
├── AGENTS.md               本机生成的“项目级钩子”（本地文件，不入库）
└── LICENSE
```

其中：

- `starter/` 才是部署模板；真正使用时，把 `starter/*` 与门禁脚本目录 `scripts/` 一起拷到你的笔记库/工作区根。
- 仓库根的 `AGENTS.md` 不是通用模板，而是一份为本机 `live-diagram` 项目生成的**项目级钩子**，里面含本机绝对路径。它通过 `.git/info/exclude` 排除在版本库外，符合系统“含真实路径的派生文件只留本地”的约定。
- `.gitignore` 忽略的是脚本报告、备份、编辑器文件等，不代表真实记忆库的隐私配置；真实记忆库应按 §13 单独配置。

### 3.2 部署后的工作区结构

```text
你的工作区根/
├── AGENTS.md                      工作区入口：地图、硬规则、同名文件消歧
├── Templates/
│   ├── Memory-Note.md             普通记忆笔记模板（只给壳）
│   └── Memory-Inbox-Note.md       Inbox 登记模板
└── Memory/                        记忆库本体
    ├── AGENTS.md                  铁律短钩子（分发到各工具）
    ├── _index.md                  唯一入口
    ├── Rule.md                    规则目录页：操作 → 分节映射
    ├── rule/
    │   ├── 写入与禁止.md
    │   ├── 收尾与维护.md
    │   ├── 子代理与脚本.md
    │   └── vibe-coding.md
    ├── Todo.md                    全局总待办
    ├── Preferences/               偏好
    ├── Plans/                     长期规划
    ├── Decisions/                 决策（专用索引手工维护）
    ├── Lessons/                   教训
    ├── Workflows/                 固定流程/SOP
    │   └── 记忆库自动审核与人工入口.md   每日 Inbox 审核 SOP（_index §五 指针）
    ├── Projects/
    │   ├── _index.md              项目索引（脚本生成）
    │   ├── <项目名>/
    │   │   ├── _overview.md       项目概况（四要素）
    │   │   └── working/
    │   │       ├── journal.md     过程流水（暂存层）
    │   │       ├── plan.md        计划
    │   │       └── completed.md   结案归档（带日期、结果、原因与来源）
    │   └── 示例项目/              骨架自带占位项目
    ├── Inbox/
    │   ├── YYYY-MM-DD.md          写入登记簿（每天一个文件）
    │   └── Archive/               审核结案留档
    └── Archive/                   季度归档
```

### 3.3 三个入口各管什么

| 入口 | 位置 | 作用 | 谁读 |
|---|---|---|---|
| 工作区入口 | 工作区根 `AGENTS.md` | 说明工作区有哪几面、硬规则、同名文件消歧 | 任何 AI 进入工作区时 |
| 记忆库钩子 | `Memory/AGENTS.md` | 铁律短版，分发到各工具系统提示 | AI 需要写记忆/收尾时 |
| 记忆库入口 | `Memory/_index.md` | 分层地图、读取路由、成本约定、读时时效 | AI 需要背景/找东西时 |

`Memory/Rule.md` 不是“全文规则”，而是**目录页**：它只回答“当前操作该读哪个分节文件”，避免每次会话通读全部规则。

## 4. 目录逐项说明

### 4.1 入口与规则文件

| 文件 | 角色 | 维护方式 | 何时读 |
|---|---|---|---|
| 工作区根 `AGENTS.md` | 工作区总表 + 硬规则 + 同名文件消歧 | 手工/项目级钩子生成 | 进入工作区第一站 |
| `Memory/AGENTS.md` | 铁律短钩子，约一屏；工具常驻指令的正本 | 手工 | 写记忆、收尾、派发子代理 |
| `Memory/_index.md` | 唯一入口：分层地图、典型路由、读取成本、读时时效 | 结构变化时手工；索引行由脚本生成 | 会话开场、找东西 |
| `Memory/Rule.md` | 规则目录页：操作 → 分节文件 | 手工 | 定位该读哪节规则 |
| `Memory/rule/写入与禁止.md` | 写入分类、待办、journal、Inbox、frontmatter、禁止位 | 手工 | 写入/登记/审核时 |
| `Memory/rule/收尾与维护.md` | 四步收尾、季度维护、五道门禁 | 手工 | 收尾/季度维护时 |
| `Memory/rule/子代理与脚本.md` | 子代理透传、脚本约定、版本管理 | 手工 | 派子代理/改脚本/处理 git 时 |
| `Memory/rule/vibe-coding.md` | 决策笔记格式与生命周期、流程笔记格式 | 手工 | 大型项目开发时 |

### 4.2 六个内容层

| 层 | 放什么 | 什么时候读 | `scope` |
|---|---|---|---|
| `Preferences/` | 语言、代码风格、沟通方式、汇报口径 | 需要用户偏好/协作习惯 | 必填 |
| `Plans/` | 长期规划、目标、路线图 | 需要长期规划 | 必填 |
| `Decisions/` | 背景 → 选择 → 备选方案 → 后果 | 架构/技术选型、想知道“为什么这么定” | 必填 |
| `Lessons/` | 踩坑、根因、解法、适用边界 | 排障、找已知解法 | 必填 |
| `Workflows/` | 固定流程/SOP | 找固定操作手册 | 必填 |
| `Projects/<项目名>/` | 项目档案与工作态 | 项目进度、来龙去脉 | **不填**（路径即归属） |

补充规则：

- 跨层五层（Preferences / Plans / Decisions / Lessons / Workflows）是**平铺共享**的，某篇笔记属于哪个项目靠 frontmatter `scope` 表达。
- `scope` 合法值 = `global` 或 `Projects/` 下的目录名；词表由脚本从实盘目录推导，不写死。
- `Projects/` 层内、各层 `_index.md`、`Inbox/`、`working/` 台账、整块无 frontmatter 的文件都**豁免** `scope`。
- 索引文件不填 `scope`：位置已由文件名给出，再填一份就是第二事实源。

### 4.3 根级三件与项目三件套

| 位置 | 作用 | 关键规则 |
|---|---|---|
| `Todo.md` | 全局总待办，按项目分组 | 分组名 = `Projects/` 目录名；不用勾选框 |
| `Inbox/` | 写入登记簿 | 每天一个文件；追加登记；审核后移入 `Inbox/Archive/` |
| `Archive/` | 季度归档 | `decisions-YYYY-QX.md` / `lessons-YYYY-QX.md` |
| `Projects/<名>/_overview.md` | 项目必读档案 | 只留定位/关键路径/关联资产/状态四要素 |
| `working/journal.md` | 过程流水 | 时间倒序，每日 `## YYYY-MM-DD`，暂存层 |
| `working/plan.md` | 计划 | 需要时创建 |
| `working/completed.md` | 结案归档 | 按时间正序，带结案日期、结果、原因与来源 |

**待办为什么不放项目里**：如果每个项目各放一份待办，就没有“当前所有事”的统一视图；而 `completed.md` 只回答“这个项目干成了什么”。因此 Todo 全局、归档项目化。

## 5. 读取机制

### 5.1 入口链

```text
工作区根 AGENTS.md
   ↓（门牌：记忆库在 Memory/，先读 _index.md）
Memory/_index.md
   ↓（分层地图 + 典型路由）
具体层 / 具体项目
   ↓
原文笔记
```

`_index.md` 只写“在哪、是什么、什么词能命中”，**不复制正文**。正文复制一份就是第二份事实源，必然漂移。

### 5.2 会话开场三件套

> **只读三件**：`Memory/_index.md` + `Memory/Todo.md` + `Projects/<项目名>/_overview.md`；其余按路线下钻，不通读。

这样设计的原因：

- `_index.md` 给出全局地图与路由；
- `Todo.md` 给出“现在要做什么”；
- `_overview.md` 给出“这个项目的定位、路径、状态、关联资产”。

### 5.3 “当前项目名”怎么取

按顺序：

1. 项目根 `AGENTS.md` 里的 `**当前项目名：`X`**`——由 `sync_memory_instructions.py --projects` 生成，是全链路唯一把项目名填成真值的地方；
2. 该文件不存在 → 从当前工作目录推断（取路径中的项目段目录名）；
3. 仍推断不出 → **问用户，不猜**。

用户级钩子不再写 `<项目名>` 字面占位，而是写「不预填，运行时按 `_index.md` §七 判定」；所以不能指望用户级指令直接给出当前项目名。

### 5.4 典型路由

| 需求 | 路线 |
|---|---|
| 续开发某项目 | `Projects/<项目名>/_overview.md` + `working/journal.md` 近期 + `Todo.md` 对应分组 |
| 架构/技术选型 | `Decisions/`（先看其 `_index.md`） |
| 排障/踩坑 | `Lessons/` |
| 用户偏好/协作习惯 | `Preferences/` |
| 固定流程/SOP | `Workflows/` |
| 找项目相关但平铺在跨层的笔记 | grep `scope: <项目名>` 与 `scope: global` |

### 5.5 读取成本约定

- 开场只读三件，不通读全库。
- `_overview.md` 只留四要素，细节下沉 `working/`。
- 三件套各自的体量阈值是 `scripts/todo_audit.py` 顶部的 `LIMIT_*` 策略常量；**具体数值不在文档里抄写**——阈值在脚本、实测在报告、文档只指路。
- 超标文件进“待瘦身”清单；季度维护只看项数是否下降，不逐条清零。

### 5.6 跨层反查：`scope`

跨层五层是平铺的，项目归属只能靠 frontmatter：

```yaml
---
type: lesson
scope: live-diagram   # 或 global
---
```

反查时必须同时查两条：

```text
scope: <项目名>
scope: global
```

`Projects/` 层内不填 `scope`，因为路径已经表达归属。

### 5.7 读时时效协议

这是全系统最重要的读取纪律：

> **记忆是“写下那天为真”的快照，不是现状。**

凡断言涉及以下内容，动手前先就地复测：

- 路径是否存在；
- 文件是否存在；
- 工具行为是否仍如此；
- 环境版本、目录结构是否变化。

复测手段：`Read`、`Glob`、一次探针命令。

另外两条配套：

1. **“无匹配”不等于“不存在”**：检索起点必须在 `Memory/` 内。记忆层被 `.gitignore` 忽略时，从仓库根起手的检索会对整层记忆零命中；文件被裸控制符腐蚀后还会被 ripgrep 判为二进制，所有基于检索的审计都会静默漏报。
2. **工具私有记忆位（含 auto-memory 影子层）不作证据**：查同名、查引用一律以记忆库为准。

索引里的“更新”列只表示“最后一次动笔”，**不表示“最后一次核验”**，不能当核验日期用。

### 5.8 读取前自检

```text
□ 我读的是 Memory/_index.md，而不是从仓库根盲搜？
□ 我知道当前项目名吗？不知道是否按顺序推断/询问？
□ 我读的是三件套 + 按需下钻，而不是通读全库？
□ 我要依据的断言涉及路径/文件/工具行为吗？涉及就先复测。
□ 我的检索起点在 Memory/ 内吗？“无匹配”是否可能只是检索路径不对？
```

## 6. 写入机制

### 6.1 先分类，再写最终位置

写入的第一动作不是打开文件，而是判断“这是什么类型的记忆”：

| 信息类型 | 落点 | 备注 |
|---|---|---|
| 偏好、语言、代码风格、沟通方式 | `Preferences/` | 影响 AI 行为 |
| 长期规划、目标、路线图 | `Plans/` | 不是待办 |
| 决策、选型、架构取舍 | `Decisions/` | 必须带 `status` 与“备选方案” |
| 踩坑、根因、解法 | `Lessons/` | 适合写成可复用判据 |
| 固定流程、SOP | `Workflows/` | 每步带验证点 |
| 项目事实、进度、路径 | `Projects/<项目名>/` | 先更新已有笔记，新主题才新建 |
| 当前要做的事 | `Todo.md` 对应项目分组 | 不写在项目内部 |
| 过程流水 | `Projects/<项目名>/working/journal.md` | 暂存层，收尾蒸馏 |
| 计划 | `Projects/<项目名>/working/plan.md` | 需要时创建 |
| 已完成事项 | `Projects/<项目名>/working/completed.md` | 从 Todo 移走 |
| 写入登记 | `Inbox/YYYY-MM-DD.md` | 每次写完追加 |

原则：**更新旧记忆优先于新建**；只有新主题才新建笔记。原地动态更新，不散建“会话笔记”。

### 6.2 frontmatter 规范

普通记忆笔记：

```yaml
---
type: lesson          # 见下方词表
created: 2026-10-23
updated: 2026-10-23
tags: [记忆库, 门禁]
scope: global         # 仅跨层五层必填；Projects/ 内不填
via: 哪次会话 / 哪个项目 / 用户口述
---
```

要点：

- `type` 合法值：`preference` / `plan` / `decision` / `lesson` / `workflow` / `project-fact` / `reference`。
- `type` 词表只有一处正本：`rule/写入与禁止.md` 第 5 条的括号清单。`todo_audit.py` 机读它，脚本内不写死第二份。
- `scope` 只在跨层五层必填；取值 = `global` 或 `Projects/` 下的目录名。
- `via:` 用于追溯来源，便于去重和复核。
- `updated` 表示“动过笔”，不是“核验过”。
- `reference` 是“指路型条目”：正文只登记某信息在别处的落点，不复制被指处的内容。

### 6.3 笔记正文模板

`Templates/Memory-Note.md` 给出四段结构：

```markdown
## 结论 / 事实
一条一个断言；不写“如上”“本次”“刚才”这类依赖上下文的指代。

## Why
为什么记下这条：触发场景 + 不记会付出什么代价。

## How to apply
下次怎么用；什么时候该套用，什么时候**不该**套用（边界）。

## 证据 / 实跑
实测数字、命令、脚本路径只落在这里；规则正本与入口文档不复制这些内容。
```

设计意图：

- “结论/事实”保证脱离会话也能读懂；
- “Why”防止记忆变成无来源的断言；
- “How to apply”强制写出边界，避免在错误场景误用；
- “证据/实跑”把易漂移的实测放在正文，而不是抄进规则文档。

模板只给壳；`type` 取值与 `scope` 口径以规则正本第 5 条为准，模板不复制判据。

### 6.4 待办规则

```markdown
## 项目名

- 一条待办
- 另一条待办
```

硬规则：

1. **分组标题一律取 `Projects/` 下的目录名**，不另起会话名/事项名分组。分组名与项目目录对不上，归档就无处落地。
2. **不用勾选框**。Todo 不是勾选清单，而是“尚未移走的条目”。
3. **结案 = 移走**：追加到 `Projects/<项目名>/working/completed.md`（带结案日期、结果、原因与来源），并从 `Todo.md` 删除该条。两件事必须同时做。
4. 项目若尚无 `working/completed.md`，**先建文件再归档**，不因缺文件把条目留在 Todo。
5. “不做”也是结案：取消 / 拒绝 / 不再继续的条目，以「已取消 / 不纳入 / 已终止」等明确结果归档到 `completed.md`，不在 Todo 里永久保留删除线；历史删除线条目按授权范围逐步迁出。
6. 计划放 `working/plan.md`，不要塞进 Todo。

### 6.5 journal 规则

`working/journal.md` 是过程流水、暂存层，不是记忆本体：

- 时间倒序，每日一个 `## YYYY-MM-DD` 小节；
- 当日粗记即可；
- 有长期价值的条目标「候选」；
- 收尾时把「候选」蒸馏到 `Decisions/`、`Lessons/` 等最终位置，原文留痕；
- 体量超过阈值时，把旧段压缩为「阶段小结」：只留结论 + wikilink 指向已转正笔记；
- **判压面只收 `journal.md`**：`working/completed.md` 属终态层，没有按日小节、无「旧段」可切，只进体量观测面，不判压；
- **阈值不在规则文档里维护**，见 `scripts/todo_audit.py` 顶部 `LIMIT_STAGING_CHARS` 常量；
- 凡声称“已并入 Todo / 已记入待办”，必须写成可核对的形态：

```text
Todo → 「条目在 Todo 里的标题片段」
```

只写“已并入 Todo ## 某组”这类机器无法核对的话，条目可能静默丢失。`todo_audit.py --check` 会核对引号里的标题是否真的出现在 `Todo.md` 或任一 `working/completed.md` 中。

### 6.6 Inbox 登记规则

AI 每次写完记忆，都要在 `Inbox/YYYY-MM-DD.md` 登记：

- **每天一个文件**，同一天多次写入追加到同一文件的「内容」列表，不按任务散建；
- **编号只在所属「内容」列表内有效**；同一天多个追加块各自从 1 起是预期形态，不追改旧块、不为凑连续而重排；
- 跨块/跨文件引用某条时不写裸编号，改写「软件 + 项目 + 条目首句加粗短语」这类可 grep 的锚；
- frontmatter：`type: inbox`、`created`、`tags`；**`软件` 只写正文、不进 frontmatter**（同一文件可有多个工具写的块，文件级单值表达不了）；
- 正文包含：日期、软件、项目、内容清单、落库位置与文件列表、`- [ ]` 待审核；
- **禁止抄正文**，只记路径 + 一句话摘要。

模板：

```markdown
---
type: inbox
created: 2026-10-23
tags: [inbox, 项目名]
---

- [ ] 待审核
- 日期：2026-10-23
- 软件：Claude Code
- 项目：项目名
- 内容：
  1. 本次写入的事项摘要
- 落库位置：
  - `Memory/Projects/<项目名>/_overview.md`
  - `Memory/Lessons/<笔记名>.md`
```

审核流程（完整 SOP 见 `Workflows/记忆库自动审核与人工入口.md`）：

1. 定期审“登记日期早于当天”的日记账；
2. 检查格式合规、落库文件存在性分级核对、重复/冲突抽查、决策格式门检；
3. 全部通过 → 把登记文件移入 `Inbox/Archive/`（保留日期名）；
4. 有异议或实质问题 → 不归档、不动，必要时挂到 `Todo.md` 的 `## 记忆库` 分组；人工可直接改目标文件并备注。

Inbox 是“写入留痕”，不是待办清单；它让 AI 的无人值守写入可被发现、可被纠错。

### 6.7 项目概况与决策索引

**`_overview.md`** 只留四要素：

- 定位：项目是什么、为什么存在；
- 关键路径：代码/资产/配置在哪；
- 状态：进行中/暂停/封存，最近变化；
- 关联资产：相关项目、上游、文档、决策链接。

细节下沉 `working/journal.md`、`working/plan.md`。

**`Decisions/_index.md`** 是唯一手工维护的层索引，格式：

```text
[YYYY-MM-DD] [分类] 决策项 → 选定方案 | 原因 | via:来源
```

分类前缀：`[架构]`、`[工具]`、`[约定]`、`[性能]`、`[安全]`。索引只作导航，不替代详笔记。**每张决策卡必须有一行带 `[[Decisions/<文件名>]]` 锚点**，且每个锚点都要指向真实文件；`mem_index.py --check` 会做双向守恒检查，但不会代写索引行。

### 6.8 项目约定文件镜像

仅当项目根**确有手写**的 `AGENTS.md` / `CLAUDE.md` 等约定文件时：

- 内容有变化 → 同步一份同名副本到 `Projects/<项目名>/`；
- 项目根没有此类文件 → 本条不适用；
- `sync_memory_instructions.py --projects` 自动生成的项目根 `AGENTS.md`（首行带“自动生成，勿手改”）**不镜像**——它本身是派生物，重跑即得。

### 6.9 索引更新

新增、改名、删除记忆笔记后，**不要手工改各层 `_index.md`**，跑：

```bash
python scripts/mem_index.py --write
```

- 自动补行/删行；
- 人工润色过的「一句话定位 / 关键词」会保留；
- “更新”列刷新为实盘事实；
- `Decisions/_index.md` 例外，手工维护。

### 6.10 禁止与例外

明确禁止写入：

- 项目内：`.workbuddy/memory/`、`.memory/`、`.trae/`、`.agent/`、`.agents/`；
- 用户级：`~/.workbuddy/MEMORY.md`、`~/.claude/`、`~/.codex/` 等；
- 任何 AI 软件在项目内私设的内部记忆目录。

唯一例外是工具自己的 auto-memory 影子层，按 §2.3 处理。

其他禁止/边界：

- 不把记忆写进规则文件；
- 用户手改的文件绝不自动改，改动前逐条确认；
- 决策反转 = 新建决策笔记并指向旧笔记，不覆盖原件；
- 发现历史残留目录 → 不续写，蒸馏进库后提示用户自行删除，不擅自删。

## 7. 结案、归档与审核

### 7.1 结案 = 移走

待办结案时（完成或取消），按顺序做两件事：

1. 把条目**追加到** `Projects/<项目名>/working/completed.md`，带结案日期、结果、原因与来源；
2. **从 `Memory/Todo.md` 删除该条**。

> 两步缺一即视为未收尾。

为什么不用 `✅`：

- Todo 会变成填埋场，三个月后分不清“真完成”“放弃”“忘记移走”；
- 规则曾一处写“移入”、一处写“追加到”，差一个动词，归档就只做一半，最终静默积累“已标完成却未移走”的条目。

### 7.2 “不再继续”的条目

“不做”也是结案：不留在 Todo 里永久打删除线，而是以明确结果归档到 `completed.md`，从 Todo 删除：

```markdown
- 2026-10-23 已取消「旧方案：迁移到 X」——原因：Y 已替代（来源：某次会话）
```

这样决策留痕，同时让总 Todo 只保留仍需行动或裁定的事项。历史删除线条目按授权范围逐步迁出，不批量改动无关项目。

### 7.3 审核与季度归档

| 动作 | 触发 | 落点 |
|---|---|---|
| Inbox 审核 | 定期（可定时任务） | 通过后移入 `Inbox/Archive/` |
| 决策/教训归档 | 每季度，或条目显著膨胀 | `Archive/decisions-YYYY-QX.md` / `Archive/lessons-YYYY-QX.md` |
| 原位标记 | 归档时 | 笔记顶部加 `status: archived-YYYY-QX` + wikilink |
| 不归档 | 活跃决策、未验证踩坑、近 90 天、用户仍在引用 | 留在原层 |

归档时把长论证压缩为“结论 + wikilink 指向原始笔记”，保留不死链。

## 8. 会话收尾与定期维护

### 8.1 四步收尾 checklist

> 一次性脚本、单轮问答可跳过；日常开发会话必须执行。

1. **待办同步**：本会话完成或取消的事项追加到 `working/completed.md`（带结案日期、结果、原因与来源）并从 `Todo.md` 删除；过程流水追加到 `journal.md` 新日期小节。
2. **持久信息落库并登记**：journal 中标「候选」的条目蒸馏到最终位置；新建决策笔记当场合规（`status` + 「备选方案」节）；写完在 `Inbox/YYYY-MM-DD.md` 登记。
3. **概况变化**：更新 `_overview.md`。
4. **约定文件与指令同步**：项目根确有手写 `AGENTS.md`/`CLAUDE.md` 时做镜像；每次收尾跑 `python scripts/sync_memory_instructions.py --check`（含声明位伪值检查），不一致就重新部署，不手工覆写。

### 8.2 季度维护

每季度末（或 Lessons/Decisions 显著膨胀时）做：

1. 审查 `Decisions/` 与 `Lessons/`，归档 >90 天、已固化、不再变动的条目；
2. 写入 `Archive/decisions-YYYY-QX.md` / `lessons-YYYY-QX.md`；
3. 原位加归档标记 + wikilink；
4. 不归档活跃决策、未验证踩坑、近 90 天条目。

### 8.3 门禁清单

| 门禁 | 命令 | 拦什么 | 性质 |
|---|---|---|---|
| ① 索引 | `python scripts/mem_index.py --check` | 索引缺行/失效行、索引「更新」列滞旧、地图页漏列、决策锚点失衡、读时时效失明 | 硬门禁 |
| ② 待办归档 | `python scripts/todo_audit.py --check` | 完成信号残留、分组名不映射、Todo 假声明、`type` 词表外取值 | 硬门禁 |
| ③ 编码/控制符 | `python scripts/encoding_guard.py <记忆库路径>` | 非 UTF-8/BOM、权威面裸控制符 | 硬门禁 |
| ④ `scope` 词表 | `python scripts/todo_audit.py --scope-check` | `scope` 非法取值、冗余出现 | 季度硬门禁 |
| ⑤ 消歧单源 | `python scripts/mem_index.py --check` | 正本表结构破损、索引侧长出第二份表、指针路径/节名失效 | 硬门禁（与①同一次运行） |
| 报告项 | `python scripts/todo_audit.py` | 开场成本、`scope` 缺字段、暂存层体量、`completed.md` 缺失、Inbox 审核积压 | 只报告（默认） |
| 指令同步 | `python scripts/sync_memory_instructions.py --check` | 真源与各工具位漂移、真源裸控制符、声明位伪值 | 收尾第④步 |

**命名冲突提示**：

- “收尾第④步”指的是 `sync_memory_instructions.py --check`；
- “季度门禁 ④”指的是 `todo_audit.py --scope-check`。

两者都写作“④”，但属于不同清单：前者是每次收尾，后者是季度维护。阅读规则原文时要看上下文。

### 8.4 门禁设计原则

- **先确认门能绿，再装门**：拿存量脏数据当门禁，等于把每次检查调成恒红。
- **恒红的门禁等于没有门禁**：历史欠账只提示不拦，可当场清零的才拦。
- **失明的门最危险**：解析失败必须退出码 1，不能静默通过。
- **门的失效形态要被测试**：用一次性探针在临时树里断言“会红的形态”真的会红。
- **靠人记得的约定必然失效**：要么门禁化，要么明示接受它失效。

## 9. 门禁脚本深入

四个脚本都只用 Python 标准库（3.9+）。它们共用记忆库定位逻辑：

1. 环境变量 `AI_MEMORY_DIR`（直接指向 `Memory/`）；
2. 从当前目录或脚本位置向上探测名为 `Memory`、且含 `Todo.md` / `_index.md` / `rule/` 之一的目录。

因此脚本可以放在 vault 根或任意子目录运行；也可以显式指定。

### 9.1 `mem_index.py`：索引生成与校验

```bash
python scripts/mem_index.py --write                 # 生成/更新
python scripts/mem_index.py --check                 # 门禁
python scripts/mem_index.py --write --layer Lessons # 只处理某层
python scripts/mem_index.py --write --refresh-cells # 强制按实盘重算人工定位/关键词
```

覆盖层：`Preferences`、`Plans`、`Lessons`、`Workflows`、`Projects`；**`Decisions` 除外**（专用格式，手工维护，只可 `--check`）。

生成逻辑：

- 扫描层内 `*.md`（跳过 `_index.md` / `README.md`）；
- 从 frontmatter 的 `summary` / `description`，或正文首个实质段落，生成“一句话定位”；正文无普通段落时，用 `**Why：** 正文` 这类加粗标签行兜底；
- 从 `tags` 生成关键词（过滤 `lesson` / `workflow` / `plan` / `preference` 等泛标签）；
- “更新”列取 `updated` / `created` / 文件 mtime；
- **合并式生成**：已有行的人工“定位/关键词”保留，只增删行；更新列始终刷新；
- `Projects` 层以项目目录为行单位，读 `_overview.md`。

`--check` 检查：

- 缺失行：实盘有新笔记但索引没有；
- 失效行：索引有但文件已不存在；
- **索引「更新」列滞旧**：比行名与「更新」列；滞旧行附 mtime 归因。**「一句话定位 / 关键词」是人工润色值，`--write` 不覆盖已有人工行**——改笔记摘要/标签不会自动刷新这两格；
- 手工地图页是否漏列顶层项（`Memory/_index.md` 必查，工作区根 `_index.md` 存在时才查）；
- **消歧单一正本**：工作区根 `AGENTS.md` §同名文件消歧的表结构（五组、三列、无重复），以及 `Memory/_index.md` §六 指针的路径与节名是否有效；标题、表格、指针只认真 Markdown 内容；
- **决策锚点守恒**：每张决策卡都有一行带 `[[Decisions/文件名]]`，每个索引锚点都指向真实文件；
- **读时时效**：`Memory/_index.md` 的「读时时效」小节必须唯一存在，且判据指针（默认指向 `Lessons/批量改写脚本的自检失明.md`）未被抽走。

退出码：`0` 干净；`1` 有漂移；`2` 记忆库不存在/层名未知/试图 `--write` 生成 `Decisions`。

设计细节：

- 索引表头也是派生物：手改表头会在下次 `--write` 被覆盖，要改表头改脚本常量。
- `--check` 现在会校验「更新」列，不再只比路径集合；滞旧就跑 `--write`。定位/关键词是人工所有，不受自动刷新影响；要强制按实盘重算两格用 `--write --refresh-cells`。
- 消歧表从“两处逐字一致”收敛为“单一正本 + 指针”：不再需要人工同步两份表。

### 9.2 `todo_audit.py`：待办归档体检

```bash
python scripts/todo_audit.py                # 全量报告 → scripts/_out/todo_audit.txt
python scripts/todo_audit.py --check         # 门禁
python scripts/todo_audit.py --cost-check    # 开场成本超标 → 退出码 1（季度）
python scripts/todo_audit.py --scope-check   # scope 非法/冗余 → 退出码 1（季度）
python scripts/todo_audit.py --inbox <目录> --audit-date YYYY-MM-DD  # 积压计数 fixture
python scripts/todo_audit.py --json          # 机器可读
python scripts/todo_audit.py -o <文件>       # 指定报告落点
```

扫描项：

| 项 | 内容 | 默认 `--check` 是否拦 |
|---|---|---|
| 完成信号残留 | Todo 条目含 `✅`、`✔`、`已完成：`、`已结清`、`已归档` 等强信号却未移走 | 拦 |
| 分组名映射 | `## 分组` 标题必须等于 `Projects/` 下的目录名（允许尾随括号说明） | 拦 |
| `completed.md` 存在性 | 被 Todo 引用的项目是否有 `working/completed.md` | **只报告** |
| 开场成本 | `_index.md`、`Todo.md`、最大 `_overview.md` 的体量 | 只报告（`--cost-check` 时拦） |
| `scope` 词表 | 跨层笔记 `scope` 非法取值；`Projects/` 或 `_index.md` 上冗余出现 | 只报告（`--scope-check` 时拦） |
| Todo 假声明 | journal/plan 里 `Todo → 「标题」` 的标题在 Todo 与所有 `completed.md` 都查不到 | 拦 |
| 暂存层体量 | **判压面只收 `journal.md`**；`completed.md` 只进观测面 | 只报告 |
| `type` 词表 | frontmatter `type` 是否在规则正本第 5 条词表内 | 拦（词表外取值） |
| Inbox 审核积压 | `Inbox/` 根下登记日期早于运行当天的文件份数 | 只报告 |

判定细节：

- 完成信号只认强信号；整行含 `~~` 的**历史**“不再继续”条目豁免；新结案应写入 `completed.md`，不新增永久删除线；引用块 `>` 跳过。
- 分组名匹配时会去掉结尾括号补充说明，例如 `## 项目（说明）` 可匹配 `项目`。
- `Todo → 「…」` 的核对面 = `Todo.md` ∪ 所有 `working/completed.md`；只查 Todo 会在条目归档当天误判红。
- 无指针形态的旧“已并入 Todo”声明只提示不拦（历史欠账）。
- `type` 词表解析失败 → 退出码 1；这是“失明的门”防护。
- 跨层笔记缺 `scope`、有 frontmatter 却缺 `type` 只提示不拦；补字段是写入侧义务。
- Inbox 积压只报不拦；计数不为零可能是审核任务没跑，也可能是“待本人决定”把整份扣住。

退出码：`0` 干净；`1` 有违规/找不到 Todo/词表解析失败。

### 9.3 `encoding_guard.py`：编码与裸控制符门

```bash
python scripts/encoding_guard.py <路径>                 # 体检
python scripts/encoding_guard.py <路径> --fix --backup  # GBK/BOM → UTF-8（先备份）
python scripts/encoding_guard.py <路径> --no-ctrl       # 跳过控制符段（大树快扫）
```

检查两类问题：

1. **编码**：非 UTF-8、UTF-8 BOM、未知编码；可自动转码 GBK/GB18030，保留换行符，不动二进制。
2. **裸控制符**：AI 把 `\a \b \f \r \t \v` 当转义吃掉后残留的 C0/DEL，包含：
   - 不构成 CRLF 的裸 CR；
   - “正文后紧跟字母”的吞字形态 TAB；
   - 缩进/行尾对齐 TAB 不算违规。

关键设计：

- **权威面** = 路径含 `Memory` 的文件；只有权威面控制符拦门禁，其余面只报告。否则抓取素材等清不掉的存量会把门变成恒红。
- **控制符只报告不自动改**：被吞的是原文那个字母，脚本无从推断，必须按实盘核对原意后手工补回。
- 这类文件会被 ripgrep 判为二进制，对所有基于检索的审计隐形；因此编码门是“检索式校验”能成立的前置条件。

退出码：`0` 干净；`1` 有需处理项/转码后仍有残留；`2` 路径不存在。

### 9.4 `sync_memory_instructions.py`：指令分发同步

```bash
python scripts/sync_memory_instructions.py              # 部署到各工具位（幂等）
python scripts/sync_memory_instructions.py --check      # 只读比对 + 真源体检
python scripts/sync_memory_instructions.py --projects   # 部署项目级钩子
python scripts/sync_memory_instructions.py --projects --check
```

单一真源：

- 用户级完整指令正文 = `Memory/Workflows/AI工具自定义指令-完整版.md`；
- 项目级最小版正文 = `Memory/Workflows/AI工具自定义指令.md` §二 的 `text` 代码块（运行时抽取，不另存副本）。

能力：

- `file` 目标：优先软链到真源；Windows 无权限时退化为复制（先备份原文件）；
- `json-inject` 目标：把真源正文注入 JSON 配置的指定键；
- `--projects`：在代码项目根生成 `AGENTS.md`，内容 = 最小版 + 真实项目名 + 本项目读取路径；
- `--check`：逐字比对真源与各部署位，并体检真源裸控制符；同时检查五个入口文件（真源 / 分发手册 / `Memory/AGENTS.md` / `Memory/Rule.md` / 工作区根 `AGENTS.md`）的「当前项目名」不得写回 `<项目名>` 伪值；漂移退出码 1；
- 部署前备份到 `<vault>/backup/`；
- 幂等，可反复跑。

安全约定：

- `TARGETS` 默认全注释——clone 后直接跑不会碰任何工具位；
- 项目级钩子已存在且不是本脚本生成 → 不覆盖（`[KEEP]`）；
- 无唯一代码根 → 只报告不猜（`[NOROOT]`）；
- `Memory/AGENTS.md` 与 `Memory/Rule.md` **不在同步范围**；改铁律时按需同步短钩子（它是精简版，不是逐字副本）。

### 9.5 硬门禁与报告项的划界

| 类型 | 例子 | 为什么 |
|---|---|---|
| 硬门禁 | 索引缺行、完成信号残留、Todo 假声明、`type` 词表外取值、编码腐蚀、指令漂移 | 存量可当场清零，或后果严重 |
| 报告项 | 开场成本、暂存层体量、缺 `scope`、缺 `type`、`completed.md` 缺失、Inbox 审核积压 | 历史欠账/渐进动作，硬拦会恒红 |
| 季度硬门禁 | `--cost-check`、`--scope-check`、归档审查 | 定期集中处理，不打扰每次收尾 |

这条划界是整套体系最核心的工程经验：**门禁不是越多越好，而是“每次都能绿”才有意义。**

### 10.1 三份指令，各司其职

| 文件 | 形态 | 用途 |

### 10.3 用户级 vs 项目级

- **用户级全局指令**：跨工作区生效；正文里「当前项目名」只写指针（不预填，按 `_index.md` §七 判定），路径可能需要一次性改成记忆库绝对路径。

```text
4. 跑 sync_memory_instructions.py --check，确认逐字一致。

```

## 11. 决策、流程与大型项目规则

### 11.1 决策笔记

`Decisions/` 每条笔记必须：

- frontmatter 含 `status`；
- 正文含「备选方案」节。

```markdown
---
type: decision
scope: <项目名或 global>
status: proposed | implemented | rejected-<一句话理由> | superseded-by-[[新笔记]] | archived-YYYY-QX
created: YYYY-MM-DD
updated: YYYY-MM-DD
tags: [...]
via: ...
---

# <决策标题>

## 背景
动机；独立于方案可读。

## 决策
implemented 用现在时；proposed 用将来时。

## 备选方案
每条真实备选 + 为什么没选。
无法重建时留 `<!-- alternatives-not-recorded (历史遗留) -->`。

## 后果
付出了什么 + 换到了什么。
```

生命周期：

1. **新增前先 grep `Decisions/` 标题关键词**；同主题旧笔记存在 → 互链。
2. 完全推翻 → 旧笔记加 `status: superseded-by-[[新笔记]]`；部分推翻 → 两条都留 active、互链，并更新旧笔记中仍现行的事实。
3. 落地后 `proposed` → `implemented`，把“将要”改写成现在时；不留 should。
4. >90 天、已固化、不再指导未来工作的 implemented 决策 → 归档到 `Archive/decisions-YYYY-QX.md`，原位留 `status` + wikilink；归档后冻结，不作现行依据。

“备选方案”是强制项：没有备选的决策无法被将来重新评估。

### 11.2 流程笔记

`Workflows/` 每条 SOP 必须是步骤化 how-to：

```markdown
## 前提
开始前必须已成立的状态 / 文件 / 工具。

## 步骤
1. <动作> → 验证：<可观测的成功信号>
2. <动作> → 验证：...

## 收尾
归档 / 登记 / Todo 同步动作。
```

规则：

- **每步带验证点**：文件存在、脚本退出码、输出含某字符串等可观测信号；“做 X”不是流程，“做 X → 验证 Y”才是。
- 不复述决策论证；涉及“为什么这么做”链向 `Decisions/<笔记>`。
- 会话内改流程就改对应 `Workflows/` 笔记，不留“以后补”。

### 11.3 Vibe coding 触发条件

以下情况触发 `rule/vibe-coding.md`：

- 代码项目里多文件开发；
- 跨会话开发；
- 涉及架构/技术选型。

单文件修改、一次性脚本、单轮问答不触发。

## 12. 子代理与上下文

派发子代理/子任务时，父会话必须把记忆库入口写进子代理指令，否则子代理会“失联”。

透传模板（原样粘贴到子代理指令开头）：

```text
记忆库位于工作区根 Memory/（权威规则 = Rule.md 目录页 + rule/ 分节文件，
写前先按操作读对应分节；结构与读取路由见 _index.md）。
当前项目名：由父会话填入真值；填不出时按 _index.md §七 判定。
你的第一动作：Read Memory/Rule.md（目录页）并按其中映射读对应分节文件，
回传一句确认；完成重要工作须回传「是否需落记忆库」。
若你被限制为只读子代理：发现需落库内容时不得静默，
须在回传中显式列出待落库条目，由父会话代写。
```

上下文被压缩/很长时，规则细节可能丢失：此时以“读 `Rule.md` 目录页定位后读对应分节”为准，不凭记忆猜。

若完成重要工作但上下文里完全没有记忆库入口（例如工具未注入 `AGENTS.md`），应主动询问用户“是否记入记忆库”，不静默跳过。

## 13. 版本管理与隐私边界

### 13.1 记忆库内不建 `.git`

记忆层与公开内容共用仓库时，私密笔记有被误推上公开远端的尾部风险。系统用两层守卫：

1. `.gitignore` 忽略整个记忆层（从源头不入库）；
2. 父仓 `pre-commit` 钩子**顶部**守卫：任何触碰 `Memory/` 的提交一律拒绝（防 `git add -f` 与未来误配置）。

钩子不在版本库内，换机器需手工恢复——恢复方法要文档化。

如果确需给记忆层做版本回溯，优先用编辑器的文件快照（如 Obsidian 的“文件恢复”）/ 文件历史插件；建独立本地 git 仓的收益通常不敌维护成本，且嵌套仓会被父仓判为嵌入式仓库。

### 13.2 五层隐私防线

1. **`.gitignore` 忽略整个记忆层**；
2. **`pre-commit` 钩子**拒绝任何触碰记忆层的提交；
3. **结构占位**：私有目录在公开仓以“空文件夹 + `.gitkeep`”显形——公开仓能看到结构、看不到内容；
4. **发布面白名单**：“不入库”与“不发布”是两个面，各有一份机器校验的清单；
5. **含真实路径/项目名的派生文件只留本地**，用 `.git/info/exclude` 而不是 `.gitignore` 忽略——提交 `.gitignore` 会把敏感文件名披露给远端。

本仓库就是一个例子：工作区根 `AGENTS.md` 含本机 `live-diagram` 项目路径，通过 `.git/info/exclude` 排除，不在 `git ls-files` 中。

### 13.3 公开骨架 vs 私有记忆

- `starter/Memory/` 是**演示骨架**，里面的示例内容可以公开；
- 真实使用时应把 `starter/*` 与 `scripts/` 一起拷到自己的私有笔记库/工作区，并按 §13.1 配置隔离；
- 不要因为本仓库的 `.gitignore` 没有忽略 `starter/Memory/`，就以为真实记忆库也不需要隔离。

## 14. 日常操作手册

### 14.1 会话开场

```text
1. 读工作区根 AGENTS.md（确认记忆库位置与硬规则）。
2. 读 Memory/_index.md（分层地图 + 路由）。
3. 读 Memory/Todo.md（当前待办）。
4. 读 Projects/<项目名>/_overview.md（项目定位/路径/状态）。
5. 只在需要时按路由下钻，不通读全库。
```

若当前项目名无法确定：先看项目根 `AGENTS.md` 的 `当前项目名`；再看工作目录；仍不确定就问用户。

### 14.2 新建项目档案

```text
Projects/<项目名>/
├── _overview.md
└── working/
    ├── journal.md
    ├── plan.md        （需要时创建）
    └── completed.md
```

同步：

- 在 `Todo.md` 建 `## <项目名>` 分组；
- 分组名必须与目录名完全一致；
- 相关跨层笔记补 `scope: <项目名>`；
- 跑 `mem_index.py --write` 更新 `Projects/_index.md`。

### 14.3 记录一条笔记

```text
1. 分类：preference / plan / decision / lesson / workflow / project-fact / reference。
2. 先看该层是否已有同主题笔记；有则更新，避免散建。
3. 用 Templates/Memory-Note.md 建壳；补 type/created/updated/tags/scope/via。
4. 写到最终位置。
5. 在 Inbox/YYYY-MM-DD.md 追加登记（路径 + 一句话，不抄正文）。
6. 跑 mem_index.py --write（若新增/改名/删除）。
```

### 14.4 添加/完成/放弃待办

添加：

```markdown
## 项目名

- 新待办
```

完成：

```text
1. 追加到 Projects/<项目名>/working/completed.md，带结案日期、结果、原因与来源。
2. 从 Todo.md 删除该条。
3. 跑 todo_audit.py --check。
```

放弃：

```markdown
# completed.md
- 2026-10-23 已取消「旧待办」——原因：……
# Todo.md 中删除该条
```

取消 / 拒绝 / 不再继续都按结案处理：带明确结果归档到 `completed.md`，并从 Todo 删除；不新增永久删除线。

### 14.5 记录决策

```text
1. grep Decisions/ 同主题关键词。
2. 有旧决策：互链；完全推翻则旧笔记加 superseded-by；部分推翻则两条都留 active。
3. 新建决策笔记：status + 背景/决策/备选方案/后果。
4. 在 Decisions/_index.md 补一行（必须含 [[Decisions/<文件名>]] 锚点）。
5. Inbox 登记。
```

### 14.6 记录教训

```text
1. 写清“结论/事实”，一条一个断言。
2. 写 Why：触发场景 + 不记的代价。
3. 写 How to apply：什么时候用、什么时候不该用。
4. 写证据/实跑：命令、路径、实测数字只放这里。
5. scope 填项目名或 global；Inbox 登记。
```

### 14.7 会话收尾

```text
① Todo 变更：完成/取消项 → completed.md，并从 Todo 删除；journal 追加当日小节。
② 持久信息落库 + Inbox 登记；决策笔记当场合规。
③ 更新 _overview.md（若概况变化）。
④ 项目约定文件镜像（如有）；跑 sync_memory_instructions.py --check。
然后：
  python scripts/mem_index.py --check
  python scripts/todo_audit.py --check
  python scripts/encoding_guard.py <记忆库路径>
```

### 14.8 季度维护

```text
1. 归档 >90 天已固化的 Decisions / Lessons。
2. 原位留 status + wikilink。
3. 跑 mem_index.py --check、todo_audit.py --check、
   todo_audit.py --scope-check、todo_audit.py --cost-check、
   encoding_guard.py <记忆库路径>。
4. 看报告项：成本、暂存层体量、缺 scope/type 的存量是否下降。
```

### 14.9 接入新 AI 工具

```text
1. 判断它是否自动读项目根 AGENTS.md。
2. 是 → 用最小版；否 → 用完整版。
3. 改真源（如需）→ sync_memory_instructions.py 部署。
4. --check 校验逐字一致。
5. 让 AI 复述读取/写入约定。
```

### 14.10 派发子代理

```text
1. 在子代理指令开头粘贴 §12 的透传模板。
2. 填当前项目名。
3. 要求子代理第一动作读 Rule.md 并回传确认。
4. 要求完成重要工作后回传“是否需落记忆库”。
5. 只读子代理必须列出待落库条目，由父会话代写。
```

以下是对项目 `starter/` 做检查后的结果（快照 2026-10-23）。本次更新只回填**系统层**，不搬入本机私有记忆内容。

### 15.1 自检结果

| 检查 | 结果 |
|---|---|
| `mem_index.py --check` | 通过：索引无缺行/失效行、「更新」列一致、消歧单一正本、决策锚点守恒、读时时效在场 |
| `todo_audit.py --check` | 通过：无完成信号残留、分组映射正常、无 Todo 假声明、`type` 合法；Inbox 积压报告为 1 份（示例登记，只报不拦） |

### 15.2 本次已回填的系统层变化

| # | 变化 | 落点 |
|---|---|---|
| 1 | 同名消歧从“两处逐字一致”收敛为**单一正本 + 索引指针** | 工作区根 `AGENTS.md`、`Memory/_index.md` §六、`mem_index.py` |
| 2 | 索引检查增加**「更新」列滞旧**与 mtime 归因；定位/关键词仍归人工 | `mem_index.py --check` |
| 3 | 新增**决策锚点双向守恒**检查；`Decisions` 只可 `--check`、不可 `--write` | `mem_index.py`、`Decisions/_index.md` |
| 4 | 新增**每日 Inbox 审核积压**报告；暂存层判压面只收 `journal.md` | `todo_audit.py` 报告八/十节、`rule/收尾与维护.md` |

| 7 | Inbox 登记细化：`软件` 只写正文、编号只在块内有效、不追改旧块 | `rule/写入与禁止.md`、模板 |
| 8 | 人工审核 SOP 从 `_index.md` §五 迁出为独立 Workflow | `Workflows/记忆库自动审核与人工入口.md` |

### 15.3 仍保留的设计选择

| # | 现象 | 说明 |
|---|---|---|
| 1 | 默认 `todo_audit.py --check` 不拦 `--cost-check` / `--scope-check` 的超标项 | 这两项是**季度硬门禁**：显式带参数才拦，日常收尾只报告，避免历史欠账把每次检查判红 |
| 2 | `completed.md` 缺失只报告、不纳入 `--check` 违规计数 | 新建项目、存量项目都会命中；硬拦会恒红。规则要求归档前先建文件，由审核兜底 |
| 3 | Inbox 审核积压只报告 | 成因可能是任务没跑，也可能是“待本人决定”把整份扣住；硬拦会在关机/节假日后恒红 |
| 4 | `sync_memory_instructions.py` 不同步 `Memory/AGENTS.md` 与 `Memory/Rule.md` | 有意设计：它只分发指令正文；改铁律时需单独同步短钩子，但 `--check` 会检查这两个入口文件没有写回伪值 |
| 5 | “收尾第④步”与“季度门禁 ④”都写作 ④ | 前者是 `sync --check`，后者是 `todo_audit --scope-check`；本文 §8.3 已做对照 |

### 15.4 两个结构提醒

1. **不要把发布仓库当记忆库**：`docs/`、`readme/`、`scripts/` 是发行物；真正运行的是复制后的工作区根 + `Memory/`。
2. **不要把本地项目钩子当通用模板**：本机仓库根的 `AGENTS.md` 含本机路径，已被 `.git/info/exclude` 排除；通用模板是 `starter/AGENTS.md`。

## 结语

这套系统的真正价值不在于“目录很整齐”，而在于它把三类容易腐烂的东西分别处理了：

- **知识腐烂** → 分层 + 索引 + 读时时效；
- **流程腐烂** → Todo 归档、Inbox 登记、收尾 checklist；
- **约定腐烂** → 门禁脚本、单一真源、失效形态测试。

如果只带走一句话：

> **能被机器检查的约定，不要交给记性；不能被机器检查的判断，明确留给人和流程。**
