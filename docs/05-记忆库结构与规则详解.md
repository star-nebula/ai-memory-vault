# 05 · 记忆库结构与规则详解

> **对象**：`ai-memory-vault` 发行仓库。
> **快照**：2026-10-24，Agent-first 切换后。
> **性质**：对 `starter/`、运行结构、读取路径、写入规则与门禁的说明。**本文不是规则正本**；与 `starter/Memory/` 下的文件冲突时，以正本为准。

## 1. 一页总览

这套系统把纯 Markdown 目录作为 AI 的跨会话记忆落点：

- **Agent 读取最小上下文**：普通任务只看热层；项目任务由 `memory_boot.py` 生成有界启动包；查历史由 `memory_query.py` 返回片段。
- **写入落到最终分类**：偏好、规划、决策、教训、流程、项目记忆各有固定位置；同日写入登记到 Inbox。
- **结案等于移走**：完成或取消的待办从 `Todo.md` 删除，追加到项目 `working/completed/YYYY-QX.md`。
- **只保留一个事实源**：没有第二份导航副本；工具指令由单一真源分发；阈值进脚本常量，实测进报告。
- **门禁覆盖会漂移的环节**：待办归档、编码、指令分发有退出码；启动成本、内容债和 Inbox 积压有报告。

```text
工作区 AGENTS.md
   │
   ├─ 普通任务 ──→ Memory/BOOT.md
   │
   ├─ 项目任务 ──→ memory_boot.py
   │                 └─ BOOT + _overview + _state + Todo 切片
   │
   ├─ 查历史 ────→ memory_query.py
   │                 └─ top-k 路径 + 状态 + 片段
   │
   └─ 写入/收尾 ─→ Rule.md → rule/ 对应分节
```

## 2. 设计目标与边界

### 2.1 解决什么问题

| 问题 | 这套系统的处理 |
|---|---|
| 工具之间记忆不共享 | 唯一落点是 Markdown 工作区，工具位只放指针与短钩子 |
| 会话启动读取过多 | 设硬预算，只加载项目的 overview、state 与 Todo 切片 |
| 全库检索噪声大 | 关键词检索、项目/scope 过滤、top-k 片段、默认排除失效状态 |
| 规则文件太长 | 目录页 + 分节文件，按当前操作读一节 |
| 约定靠人记得 | 能机判的变成门禁；不能清零的只报告 |
| 记忆过期仍被当成现状 | 读时复测路径、文件存在性与工具行为 |

### 2.2 不做什么

- 不引入数据库、向量库、常驻服务或外部模型 provider。
- 不要求 Obsidian 插件；Templater / Dataview 只可作为可选增强。
- 不维护人看导航页，也不为 Agent 复制整份正文做导航缓存。
- 不把工具私有 auto-memory 当正本、证据或“已查过同名”的依据。

## 4. 目录逐项说明

### 4.1 入口与规则

| 文件 | 作用 | 何时读 |
|---|---|---|
| 工作区根 `AGENTS.md` | 门牌、硬规则、启动/检索/写入命令 | AI 进入工作区 |
| `Memory/AGENTS.md` | 铁律短钩子 | 常驻工具指令或写前确认 |
| `Memory/BOOT.md` | 稳定、跨项目、短小的热记忆 | 普通任务 / 每次启动包 |
| `Memory/Rule.md` | 操作到分节文件的映射 | 写入、收尾、维护前 |
| `Memory/rule/*.md` | 具体规则 | 只读当前操作对应的一节 |

### 4.2 六个内容层

| 层 | 放什么 | 典型读取 |
|---|---|---|
| `Preferences/` | 语言、代码风格、沟通方式 | 需要用户偏好 |
| `Plans/` | 长期目标、路线图 | 需要规划背景 |
| `Decisions/` | 背景、选择、备选、后果 | 想知道“为什么这么定” |
| `Lessons/` | 踩坑、根因、适用边界 | 排障、避免重复犯错 |
| `Workflows/` | 固定步骤与验证点 | 执行可复用流程 |
| `Projects/<项目名>/` | 项目事实、状态、过程与结案 | 项目任务 |

### 4.3 项目结构

```text
Projects/<项目名>/
├── _overview.md        项目定位、关键路径、状态、关联资产
├── _state.md           当前目标、阻塞、下一步
└── working/
    ├── journal/YYYY-MM.md    过程流水，按月分片
    ├── plan.md               当前计划
    └── completed/YYYY-QX.md  结案归档，按季度分片
```

- `_overview.md` 是稳定项目卡片，不写每日流水。
- `_state.md` 是当前快照，变化时覆盖更新，不追加历史。
- `journal/YYYY-MM.md` 是暂存层；长期有价值的内容要蒸馏到内容层。
- `completed/YYYY-QX.md` 是终态层；完成和取消都必须从这里留痕。
- 旧单文件 `journal.md` / `completed.md` 只作为历史兼容读取，不再追加。

### 4.4 根级登记与归档

| 目录/文件 | 作用 |
|---|---|
| `Todo.md` | 仍需行动或裁定的全局待办，按项目分组，不用勾选框 |
| `Inbox/YYYY-MM-DD.md` | 每次写入的登记簿，记录路径与一句话摘要 |
| `Inbox/Archive/` | 已审核完成的每日登记 |
| `Archive/` | 季度归档的决策与教训 |

## 5. 读取机制

### 5.1 普通任务

普通问答、单轮任务、与历史无关的代码操作**不默认扫描记忆库**。需要用户偏好时只读 `Memory/BOOT.md`。

### 5.2 项目任务

运行：

```bash
python scripts/memory_boot.py --cwd .
```

启动包只读四类输入：

1. `Memory/BOOT.md`
2. `Projects/<项目名>/_overview.md`
3. `Projects/<项目名>/_state.md`
4. `Todo.md` 的当前项目切片

约束：

- `--budget` 是最终 `text` 的硬上限。
- 单 section 还有独立上限；`section_truncated` 与 `budget_truncated` 分开报告。
- `files` 列出实际读取的文件；不扫描其他项目树。
- 同一会话只加载一次；除非用户要求刷新或记忆已写入。

### 5.3 查历史、原因与踩坑

运行：

```bash
python scripts/memory_query.py "关键词" --cwd .
```

默认行为：

- 返回 top-k 路径、类型、scope、status、更新日期和片段；
- 不展开整篇笔记；
- 排除 `archived` / `superseded`；
- 跳过 `Inbox/`、`Archive/`、`working/`；
- 无法识别项目时只搜 `scope: global`；
- 项目查询不越出当前项目树，跨项目必须显式 `--all-projects`。

需要历史流水时加 `--include-history`；需要失效决策时加 `--include-inactive`；限定时间窗或层级时用 `--since` / `--until` / `--layers`。月/季度分片在读取前按分片范围与时间窗做相交判断，不相关分片直接跳过。

### 5.4 当前项目名

按序取：

1. 项目根 `AGENTS.md` 中的 `当前项目名` 声明；
2. 最近的 `.git` / `AGENTS.md` 根目录名；
3. 无法确定时询问用户，不猜。

非法路径名、`..`、绝对路径和越出 `Projects/` 的符号链接一律拒绝。

### 5.5 scope

跨层五层（`Preferences` / `Plans` / `Decisions` / `Lessons` / `Workflows`）使用：

```yaml
scope: <项目名>   # 或 global
```

`Projects/` 内由路径表达归属，不填 `scope`。合法项目名从 `Projects/` 实盘目录推导；缺字段只提示，非法取值在季度门禁拦截。

### 5.6 读时时效

记忆是“写下当天为真”的快照。凡断言涉及：

- 路径或文件存在性；
- 工具行为或版本；
- 环境配置；
- Git / 服务 / 外部系统状态；

引用前必须复测。“无匹配”不等于“不存在”；检索受忽略规则、编码与范围影响。

## 6. 写入机制

### 6.1 先分类，再写最终位置

1. 偏好 → `Preferences/`
2. 长期规划 → `Plans/`
3. 决策 → `Decisions/`
4. 踩坑 → `Lessons/`
5. 固定流程 → `Workflows/`
6. 项目事实 → `Projects/<项目名>/`
7. 待办 → `Todo.md`
8. 过程流水 → 项目 `working/journal/YYYY-MM.md`

优先更新已有笔记；只有新主题才新建。

### 6.2 frontmatter

普通记忆：

```yaml
---
type: lesson
scope: demo
status: active
created: 2026-10-24
updated: 2026-10-24
tags: [memory, retrieval]
via: Codex 会话
---
```

合法 `type`：

```text
preference / plan / decision / lesson / workflow / project-fact / reference
```

要点：

- `scope` 只在跨层五层必填；
- `status` 默认 `active`；失效状态用 `review` / `superseded-by-[[新笔记]]` / `archived-YYYY-QX`；
- `verified_at` 可选，只在断言涉及路径、工具行为或环境版本时使用；它只表示该断言最后一次现场复核日期；
- `reference` 表示指路型条目，正文以指针为主；
- `updated` 只表示动过笔，不表示已核验；
- 每条记忆标明来源 `via:`。

### 6.3 正文模板

```markdown
# <脱离会话也能独立读懂的标题>

## 结论 / 事实
一条一个断言。

## Why
触发场景，以及不记会付出什么代价。

## How to apply
何时适用，何时不适用。

## 证据 / 实跑
命令、结果、日期或链接。
```

决策笔记额外要求 `status` 与「备选方案」节。

### 6.4 待办

- 统一写 `Memory/Todo.md`；
- 按 `Projects/` 目录名分组；
- 不用勾选框；
- 完成 = 追加到 `working/completed/YYYY-QX.md` 并从 Todo 删除；
- 取消 / 不纳入 / 终止同样归档，不留在 Todo 打删除线。

### 6.5 journal

时间倒序，每日一个 `## YYYY-MM-DD` 小节：

- 当日粗记；
- 长期有价值的条目标「候选」；
- 收尾时蒸馏到最终位置，原文留痕；
- 声称已并入 Todo 时必须写成 `Todo → 「标题片段」`，便于机器核对。

### 6.6 Inbox 登记

每天一个文件，同一天多次写入追加到同一文件：

- 记录软件、项目、写入路径、一句话摘要；
- 不抄正文；
- 保留 `- [ ]` 待审核；
- 审核完成后移入 `Inbox/Archive/`。

### 6.7 `_overview.md` 与 `_state.md`

- `_overview.md`：项目定位、关键路径、关联资产、总体状态；
- `_state.md`：当前目标、阻塞、下一步；
- `_state.md` 不用于流水，不保留旧目标；
- 无工作态的项目可以使用简短 state 卡，但活跃项目应在实际使用中逐步核实。

### 6.8 项目约定镜像

只有当项目根确实有手写的 `AGENTS.md` / `CLAUDE.md` 时，才同步同名副本到 `Projects/<项目名>/`。脚本自动生成的项目根钩子不镜像，避免复制派生物。

## 7. 结案、审核与归档

### 7.1 结案

```text
Todo.md 删除条目
  + working/completed/YYYY-QX.md 追加
    日期 / 结果 / 原因 / 来源
```

两步缺一即视为未收尾。

### 7.2 Inbox 审核

审核从 `Inbox/` 根下未归档文件开始：

1. 核对登记的落库路径是否存在；
2. 核对格式、scope、type 与来源；
3. 查重复/冲突；
4. 对窗口内新增决策检查 `status` 与「备选方案」；
5. 通过后整份移入 `Inbox/Archive/`；
6. 有异议时只报告，不替作者改判断性内容。

### 7.3 季度归档

- 只归档 >90 天、已固化、不再指导未来工作的决策与教训；
- 原位保留 `status: archived-YYYY-QX` 与 wikilink；
- 归档不是删除，长论证压缩后仍可追溯。

## 8. 会话收尾与维护

### 8.1 每次收尾

1. 同步 Todo 与 `completed/` 季度归档；
2. 把持久信息写到最终位置并登记 Inbox；
3. 更新变化的 `_overview.md` / `_state.md`；
4. 需要时镜像项目约定文件；
5. 跑 `sync_memory_instructions.py --check`。

### 8.2 门禁

| 检查 | 命令 | 性质 |
|---|---|---|
| 待办归档 | `python scripts/todo_audit.py --check` | 硬门禁 |
| 编码与控制符 | `python scripts/encoding_guard.py <Memory>` | 硬门禁 |
| 指令分发 | `python scripts/sync_memory_instructions.py --check` | 硬门禁 |
| scope 词表 | `python scripts/todo_audit.py --scope-check` | 季度硬门禁 |
| 启动包成本 | `python scripts/todo_audit.py --cost-check` | 结构变化时硬门禁 |
| 内容债 | `python scripts/todo_audit.py --content-check` | 严格验收/季度 |
| 全量报告 | `python scripts/todo_audit.py` | 报告项 |
| 项目状态 | `python scripts/state_audit.py` | 报告项；`--strict` 可作验收门禁 |
| 生命周期复核 | `python scripts/memory_review.py` | 报告项；`--strict` 可作季度门禁 |

原则：

- 能当场清零的才做硬门禁；
- 渐进清理项只报告；
- 解析失败必须报错，不能静默变绿；
- 报告为绿不等于内容已覆盖。

## 9. 脚本

### 9.1 `memory_boot.py`

```bash
python scripts/memory_boot.py --cwd . --json
python scripts/memory_boot.py --project demo --budget 6000
```

输出：

- `project`
- `budget` / `budget_scope`
- `chars` / `source_chars` / `assembled_chars`
- `section_truncated` / `budget_truncated`
- `files`
- `sections`
- `text`

### 9.2 `memory_query.py`

```bash
python scripts/memory_query.py "关键词" --cwd . --limit 5 --budget 5000
python scripts/memory_query.py "旧方案" --include-inactive --include-history --json
python scripts/memory_query.py "关键词" --all-projects --json
python scripts/memory_query.py "关键词" --include-history --since 2026-10-01
python scripts/memory_query.py "关键词" --layers Decisions,Lessons
```

检索是确定性的关键词匹配，不使用模型或向量。分数来自标题、标题层级、标签、正文次数和 scope 匹配；结果数量与文本预算双重受限。

### 9.3 `todo_audit.py`

```bash
python todo_audit.py                  # 全量报告
python todo_audit.py --check          # 待办/假声明/type 门禁
python todo_audit.py --cost-check     # 启动包硬门禁
python todo_audit.py --content-check  # 严格内容债
python todo_audit.py --scope-check    # 季度 scope 门禁
```

阈值放在脚本常量，实测写报告。`type` 词表从规则正本文本机读；解析失败退出码 1。

### 9.4 `encoding_guard.py`

处理非 UTF-8 / BOM 与裸控制符。转码可 `--fix --backup`；控制符只报告，因为脚本无法推断被吞掉的原始字母。

### 9.5 `state_audit.py`

```bash
python scripts/state_audit.py
python scripts/state_audit.py --json
python scripts/state_audit.py --strict
```

按 `Todo.md` 的活跃项目分组检查：

- `_state.md` 是否存在；
- 是否仍是迁移占位卡；
- `updated` 是否超过默认 30 天；
- 是否超过 1000 字符。

默认只报告；`--strict` 才在任一状态不可用时退出 1。状态必须由项目会话核实，不能批量伪造。

### 9.6 `memory_review.py`

```bash
python scripts/memory_review.py
python scripts/memory_review.py --strict --max-age-days 90
```

扫描长期内容层的生命周期与时效债：

- 缺 `status`；
- `status: review`；
- 正文含路径、工具行为、环境版本等易漂移断言，但没有 `verified_at`；
- `verified_at` 已超过阈值。

默认只报不拦，不自动改笔记。它提供的是复核队列，不是自动判真。

### 9.7 `sync_memory_instructions.py`

- 真源：`Memory/Workflows/AI工具自定义指令-完整版.md`
- `--check`：逐字比对部署位、检查裸控制符与项目名伪值
- `--projects`：新建或更新带自动生成标记的项目级钩子；已有手写 `AGENTS.md` 保持 `[KEEP]`，无唯一代码根只报告不猜
- `TARGETS` 默认全注释，clone 后直接运行不会改用户工具配置

## 10. 接入 AI 工具

### 10.1 三个层次

| 层 | 放什么 |
|---|---|
| 工作区/项目根 `AGENTS.md` | 进入该库的门牌、命令与硬规则 |
| 工具用户级自定义指令 | 一段短钩子，指向记忆库；可跨工作区 |
| 记忆库 `AGENTS.md` / `Rule.md` | 权威规则与分节路由 |

### 10.2 常见落点

| 工具 | 常见位置 |
|---|---|
| Claude Code | 项目 `CLAUDE.md` 或 `~/.claude/CLAUDE.md` |
| Codex | 项目/用户 `AGENTS.md` |
| Cursor | User Rules 或 `.cursor/rules/` |
| GitHub Copilot | `.github/copilot-instructions.md` |
| OpenCode / Gemini CLI | `AGENTS.md` / `GEMINI.md` |
| Trae / ZCode / Qoder | 各自用户规则目录或设置 |

工具位只允许放指针与短钩子；具体偏好、决策、教训必须落记忆库。

## 11. 决策、流程与大型项目

### 11.1 决策

```yaml
status: proposed | implemented | rejected-<理由> | superseded-by-[[新笔记]] | archived-YYYY-QX
```

正文必须有「备选方案」节。决策反转新建笔记并互链：

- 完全推翻：旧笔记标 `superseded-by`；
- 部分推翻：两条都保留 active，互相链接；
- 新决策写入前先检索同主题。

### 11.2 流程

每一步写成：

```text
动作 → 验证：<可观测成功信号>
```

验证点可以是文件存在、退出码、输出字符串或报告路径。为什么这样定，链接到决策笔记，不在流程中重复论证。

### 11.3 Vibe coding 触发

`E:\Projects\` 下多文件、跨会话、涉及架构选型的项目任务触发。单文件修改、一次性脚本、单轮问答不触发。

## 12. 子代理与上下文

派发子代理时：

- 在指令中写明记忆库入口与当前项目；
- 告诉它先用 `memory_boot.py` / `memory_query.py`；
- 完成重要工作后必须回传“是否需要落记忆库”；
- 只读子代理不能静默跳过，应列出待落库条目由父会话代写。

## 13. 隐私与版本边界

- 记忆内容只落 `Memory/`，不写工具私有记忆位。
- 工具 auto-memory 只当影子缓存，不作证据。
- 含路径、真实项目名或敏感配置的生成物只留本地。
- 项目根钩子优先通过 `.git/info/exclude` 忽略，不修改公开 `.gitignore`。
- 私有记忆层与公开仓库共处时，应由 `.gitignore` 和提交守卫双重隔离。

## 14. 日常操作

### 14.1 开始项目任务

```bash
python scripts/memory_boot.py --cwd . --json
```

### 14.2 查历史

```bash
python scripts/memory_query.py "关键词" --cwd . --include-history
```

### 14.3 新建项目

1. 创建 `Projects/<项目名>/`；
2. 写 `_overview.md`；
3. 写 `_state.md`；
4. 在 `Todo.md` 建同名分组；
5. 需要时创建 `working/` 三件套。

### 14.4 记录一条笔记

1. 判断分类与 scope；
2. 参考模板写最终位置；
3. 更新 `updated`；
4. 在 Inbox 登记路径和摘要。

### 14.5 完成待办

1. 追加到 `working/completed/YYYY-QX.md`；
2. 从 `Todo.md` 删除；
3. 在 journal 记录结果；
4. 跑 `todo_audit.py --check`。

### 14.6 收尾

跑：

```bash
python scripts/todo_audit.py --check
python scripts/encoding_guard.py <Memory>
python scripts/sync_memory_instructions.py --check
```

结构或内容有较大变化时再加成本/内容检查。

## 16. 一页速查

| 场景 | 动作 | 验证 |
|---|---|---|
| 普通问答 | 不扫描记忆；必要时读 `BOOT.md` | 未预读整棵记忆树 |
| 项目任务 | `memory_boot.py --cwd .` | 包在预算内，项目正确 |
| 查原因/踩坑 | `memory_query.py "关键词"` | 返回路径与片段，不展开全文 |
| 写偏好 | `Preferences/` + `scope` + `via` | Inbox 已登记 |
| 写决策 | 新笔记 + `status` + 备选方案 | 与旧决策互链 |
| 完成待办 | completed 追加 + Todo 删除 | `todo_audit.py --check` 绿 |
| 取消待办 | 同样归档，写明原因 | Todo 不再保留 |
| 会话收尾 | 四步写入 + 三道门禁 | 退出码 0 |
| 接新工具 | 真源分发 + `--check` | 工具位逐字一致 |

## 结语

这套系统不是“把所有东西记下来”，而是让 Agent 在正确的时机、用可预算的成本，读到足够做决定的最少事实。目录、命令与门禁都服从这个目标；无法降低启动成本或降低漂移风险的复杂度，不应进入结构。
