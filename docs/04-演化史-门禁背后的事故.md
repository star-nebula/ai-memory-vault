# 04 · 演化史：每个门禁背后的事故

这套体系不是设计出来的，是被事故逼出来的。每个门禁的设立依据都是一次真实复盘。以下按时间整理（日期为 2026 年）。

## 09-21 · 手工索引漂移 → 索引是派生物 + `mem_index.py`

**现象**：人看的索引页长期落后实盘 4~5 条；目录调整后索引里的条目指向已删除的文件。

**根因**：索引靠手工维护，而"新增笔记"和"更新索引"之间没有任何强制关联。

**修复**：索引改为脚本从笔记 frontmatter 生成的**派生物**；`--check` 作为门禁报"缺失行 / 失效行 / 新增未登记"。合并式生成让人工润色的一句话定位在重跑后保留。

**衍生教训**：脚本生成的索引页**表头也是派生物**——手改表头会在下次 `--write` 被覆盖，要改表头改脚本常量。这直接催生了"数字与说明不进派生物"的通则。

## 09-21 · "假成功"入库 → `.gitignore` 白名单三行式

**现象**：一次提交标题写"新增 todo_audit.py 等 5 个脚本"，`git show --stat` 实际只有 README.md，且 `git status` 显示 clean——5 个 py 全部没进库。

**根因**：`.gitignore` 写了"忽略整个目录"（`_agent_scripts/`），`git add` **静默跳过**被忽略文件。提交照样成功，消息照样写成"新增 X"。

**修复**：改用"忽略目录内容 + 白名单"三行式：

```gitignore
_agent_scripts/*
!_agent_scripts/*.py
_agent_scripts/_tmp*    # 末行后置反排除：白名单会放行临时脚本，靠"最后匹配者胜"压回
```

**制度教训**：核验"有没有入库"要看 `git ls-files`，**不是 `git status`**——被忽略的文件在 status 里根本不出现。

## 09-21 · 待办归档零门禁 → `todo_audit.py`

**现象**：静默积累 4 条"已标完成却未移走"的条目，含一条 2000 字符、与 completed.md 完全重复的复盘。

**根因**：索引漂移有门禁、断链有审计，唯独"待办 → 项目 completed.md"这条链只写在收尾 checklist 里。**无门禁的环节静默积累**。且规则一处写"移入"、另一处写"追加到"——差一个动词，归档只做一半。

**修复**：把"结案 = 移走"变成可校验项：完成信号残留、分组名与 `Projects/` 目录名映射、journal 假声明、`type` 词表外取值入硬门禁；`completed.md` 缺失先作报告项（存量/新建项目会让每次检查变红，清不到就只报告）。后来又追加：journal 里"已并入 Todo"声明的核对（见 09-30）。

## 09-26 · 双入口漂移 → 唯一入口

**现象**：`Home.md`（人看的地图）与 `_index.md`（AI 入口）并存一个月，分层条数出现第二次漂移（同一层两个页面记录的条数不一致）。

**根因**：双入口意味着同一事实存两处。

**修复**：合并为唯一入口 `_index.md`，人看的地图与人工审核节并入其中。**"入口唯一"从此成为铁律。**

## 09-29 · 裸控制符腐蚀 → `encoding_guard.py`

**现象**：一个规则文件里的 `\v` 被 AI 当转义序列"吃掉"，落盘成裸 `0x0B` 控制符，同一路径的尾反斜杠一并丢失，指针变成不可解析的 `ruleibe-coding.md`。**部署出去的那份是错的，"仅供阅读"的副本反而是对的**——坏指针在各工具存活约 7 天无人发现。

**根因**：AI 写文件时把 `\a \b \f \r \t \v` 当转义处理，正文字符被替换成控制符本身，**并吞掉后面的那个真实字母**。更阴险的是：这类文件会被 ripgrep 判为二进制，于是**对所有基于检索的审计隐形**——编码检查对它们还全判"正常"。

**修复**：`encoding_guard.py` 单开一道"裸控制符门"：C0 + DEL + 不构成 CRLF 的裸 CR + 吞字形态的 TAB。**只报告不自动改**——被吞的是原文那个字母，脚本无从推断，必须逐处以实盘核对原意后手工补回。

## 09-29 · 半部署 → 分发脚本加 `--check`

**现象**：分发同步脚本打印警告字符时被控制台编码打断（GBK 控制台 + `UnicodeEncodeError`），实测在第一处部署成功之后、第二处之前崩溃——三处工具位两旧一新，**半部署无人知晓**。

**根因**：部署链只有部署没有校验。

**修复**：脚本顶部统一 `sys.stdout.reconfigure(encoding="utf-8")`；新增 `--check` 只读比对（真源 vs 各部署位逐字一致 + 裸控制符体检），漂移退出码 1；**"改完必跑 --check"写进收尾 checklist**。通用推论：**部署类脚本必须幂等 + 配 `--check`，否则半部署无法被发现**。

## 09-30 · Todo 假声明 → 声明核对门

**现象**：journal 写着"待修项已并入 Todo"，实测 Todo 里从来没有那条——静默挂起三天。

**根因**："已并入 Todo"是机器无法核对的话。AI 会真诚地写下它以为发生过的事。

**修复**：规定合规形态 `Todo → 「条目在 Todo 里的标题片段」`——引号里必须是 Todo 行里逐字存在的文字。带指针形态却查无此条 = **假声明，门禁拦截**；无指针形态的旧写法只提示不拦。核对面 = `Todo.md` ∪ 所有 `completed.md`（"结案 = 移走"会让条目在归档当天离开 Todo，只查 Todo 会误报）。

## 09-30 · 成对表漂移 → 门禁 ⑤（10-19 收敛为单一正本）

**现象**：两张分布在不同的文件、互称"逐字一致"、各自写着"改一处必须同步另一处"的消歧表，实测漂了 2 行，且所有既有门全程无感。

**根因**：**"靠两份文件各自提醒同步" = 没有提醒。** 这两份表没有派生关系，谁也不生成谁。

**第一次修复（09-30）**：比对器并入 `mem_index.py --check`（不新增命令），差异只报**真正不同的那几个单元格**；只报告不自动改——两处都是手工文件，"以哪一行为准"是人的判断。

**第二次修复（10-19）**：既然"两份手工表"本身就是病根，干脆收敛为**单一正本**——完整五组表只允许存在于工作区根 `AGENTS.md` §同名文件消歧；`Memory/_index.md` §六 只留指针。门禁改为校验正本表结构（五组、三列、无重复）与索引侧指针有效性；标题、表格、指针塞进代码围栏或 HTML 注释一律视为失明。**从"比对两份副本"升级为"消灭第二份副本"。**

## 09-30 · 永不触发的阈值 → 口径复检

**现象**：暂存层压缩阈值"约 500 行"写死在文档里，全库 42 份暂存文件按行数**零超标**，但最重的一份实际已是几万字符。

**根因**：journal 习惯把一整段实测叙述写成一行——单行动辄上千字符，行数口径形同虚设。**一个永不报警的阈值和一个正确的阈值，在跑之前长得一模一样。**

**修复**：口径改字符数；阈值移入脚本常量（`LIMIT_STAGING_CHARS`，常量名带单位）；"把阈值移进脚本时顺手复检它测的还是不是有效的量"成为通则。

## 10-01 · 门禁自身的在场校验

最后一个反转：门禁本身也是文件，也会被改名、被删节。`mem_index.py --check` 因此校验"读时时效"小节在场、判据指针未被抽走——**改名或删除即报红**。所有失效形态（关键词只出现在正文行、指针落在别的小节等"蹭词"形态）先用一次性探针在临时树断言过。

## 10-02 · 索引更新列滞旧 → 单元格级检查（定位/关键词仍归人工）

**现象**：索引行数对得上，但「更新」列可能是旧值——只比行名会放行这种静默漂移。

**修复**：`mem_index.py --check` 增加「更新」列比对；滞旧行附 mtime 归因（实盘晚于索引生成 → 写入方漏跑 `--write`；早于 → 疑为索引侧被手改）。**「一句话定位 / 关键词」是人工润色值，`--write` 不会覆盖已有人工行**——因此本门只对「更新」列做硬校验；改笔记摘要/标签不会自动刷新人工行，需人工同步。同时给正文摘要加"加粗标签兜底"，让 `**Why：** 正文` 这类主文体也能进入一句话定位。

## 10-15 · 审核任务停跑无人知晓 → Inbox 积压报告

**现象**：定时审核任务绑在应用上，设备关机 / 节假日 / 应用未运行时记 `skipped` 且不补跑；可能连续多天零审核落地，而所有门禁全绿，没有任何一处知道。

**修复**：`todo_audit.py` 增加「每日 Inbox 审核积压」报告段——列出 `Inbox/` 根下登记日期早于运行当天的登记文件。**只报不拦**：成因可能是任务没跑，也可能是审过了但「待本人决定」把整份扣住；做成硬门禁会在关机后恒红。

## 10-21 · 结案语义扩宽

**现象**：待办除了"完成"，还有"取消 / 拒绝 / 不再继续"；如果只把完成视为结案，这类条目会长期占着总待办，或退化成永久删除线。

**修复**：**结案 = 移走**。完成与"不做"都写入 `completed.md`（带结案日期、结果、原因与来源），并从 `Todo.md` 删除；不再用永久删除线表达取消。历史删除线条目按授权范围逐步迁出，不批量改动无关项目。

## 10-24 · 索引整体退役

**现象**：即便索引不再进入启动路径，人和 Agent 仍会不断问“要不要更新索引”，脚本、规则和排障路径也保留第二套维护面；对纯 Agent 读取而言，这部分复杂度没有收益。

**修复**：删除 `_index.md` 全部分层、删除 `mem_index.py` 及其测试，改为 `memory_boot.py` 生成有界启动包、`memory_query.py` 做按需检索。目录结构只表达物理落点，不再持久化导航副本；历史文档保留当时事实，现行入口与命令不再依赖索引。

## 方法论总结

1. **每个门禁都有一次事故背书**——没有事故背书的门禁是想象中的需求
2. **先确认门能绿，再装门**——存量清不掉的检查只做报告
3. **失明的门最危险**——解析失败要退出码 1，报告瞎了要说自己瞎了
4. **门的失效形态要被测试**——恒绿与恒红同样不等于有门禁
5. **纯靠记忆与自觉的约定必然失效**——要么门禁化，要么明示放弃
