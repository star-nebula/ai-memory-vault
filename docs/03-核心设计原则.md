# 03 · 核心设计原则

这套体系能运转下去，靠的不是自律，是几条被事故反复校准过的原则。

## 一、单一事实源，其余皆派生

**同一份事实只允许存在一处，其余位置要么是指针，要么是脚本生成的派生物。**

实例：

- 各层 `_index.md` 由 `mem_index.py` 从笔记 frontmatter 生成——索引是派生物，手工补条目被明令禁止；脚本用"合并式生成"保留人工润色过的一句话定位，让"派生"与"润色"兼容
- 分发给多个 AI 工具的指令正文只有一个真源文件，各工具位由 `sync_memory_instructions.py` 派生部署——人手逐份抄写必然漂移
- `type` / `scope` 词表由脚本从规则正本 / 实盘目录名**机读推导**，脚本内不写死第二份

推论：**"同一事实两个位置"是 bug，不是冗余。** 曾有同一阈值在两个文档各存一份（数值还不一致）——后来干脆裁定"数字不进文档"：阈值 = 脚本常量（策略），实测 = 报告输出（事实），文档只留指针。

## 二、完成 = 移走，不是标注

待办完成时，条目要**追加到** `Projects/<项目名>/working/completed.md`（带日期）并**从 Todo 删除**，两件事同时做。不是在原地打个 ✅。

为什么这么苛刻？因为"就地打标"会让 Todo.md 变成填埋场——三个月后没人分得清哪些是真完成、哪些是放弃、哪些只是忘记移走。规则里的动词精度很重要：规则曾一处写"移入"、另一处写"追加到"，差一个动词，归档就只做一半，最终静默积累 4 条"已标完成却未移走"的条目（详见 [04-演化史](04-演化史-门禁背后的事故.md)）。

"不再继续"的条目**不删**，改删除线留档并注明日期与原因——决策留痕，但离开"待办"这个语义区。

## 三、写入有登记，审核有流程

AI 写记忆是无人值守操作，出错不可避免。对策不是要求 AI 不犯错，而是**让每次写入留痕、让审核成为例行流程**：

1. AI 每次写完记忆，在 `Inbox/YYYY-MM-DD.md` 追加登记：写了哪些文件 + 各一句话摘要（禁止抄正文）
2. 例行审核（本库是每日定时任务）：格式合规检查、落库文件抽验、重复/冲突核对
3. 全部通过 → 登记移入 `Inbox/Archive/` 结案；有异议 → 人工直接改目标文件并在登记中备注

人的角色被压缩到最小：看结案记录、处理挂起事项、对自动化结论行使否决权。

## 四、决策有生命周期

"为什么当初这么定"是记忆库里最值钱也最容易烂掉的信息。约定：

- 决策笔记 frontmatter 必带 `status`：`proposed` / `implemented` / `rejected-<理由>` / `superseded-by-[[新笔记]]` / `archived-YYYY-QX`
- 正文必含**「备选方案」节**：每条真实备选 + 为什么没选。没有备选的决策无法被将来重新评估
- 决策反转 = **新建笔记**并互链，绝不覆盖旧笔记（旧决策是"当时为什么这么选"的证据）
- 落地后 `proposed` → `implemented`，把"将要"改写为现在时——留着 should 的决策笔记等于没有决策
- >90 天已固化的决策按季度归档，原位留 `status` 标记

流程笔记（`Workflows/`）配套一个格式约束：**每一步必须带"验证：<可观测成功信号>"**。"做 X"不是流程，"做 X → 验证 Y"才是——验证点是文件存在、脚本退出码、输出含某字符串这类机器可判定的东西。

## 五、有门禁的环节才不漂移

这是全套体系最核心的经验。曾经以为"在两份文件里各写一句'改一处必须同步另一处'"就够了——实测漂了 2 行，且没有任何既有检查发现。反之，所有配了退出码门禁的环节（索引、待办归档、编码），从上线起再没静默坏过。

于是形成方法论：

> **凡是靠人记得的约定，都会失效。把约定变成脚本门禁（退出码非 0 即失败），或者明示接受它失效。**

配套的判定细则：

- **先确认门能绿，再装门**——拿存量脏数据当门禁，等于把每次检查调成恒红
- **恒红的门禁等于没有门禁**——"缺 scope / 缺 type"这类写入侧义务只提示不拦；"词表外取值"这类可当场清零的才拦
- **失明的门最危险**——它和绿的门长得一模一样。所以"词表解析失败必须退出码 1""报告瞎了也要说自己瞎了"
- **门禁失效形态要被测试**——用一次性探针脚本在临时树里断言"会红的形态"（改名 / 删节 / 抽取过短）真的会红，不拿真库试

## 六、隐私边界靠守卫，不靠自觉

记忆库包含个人偏好、项目内幕、求职记录级别的隐私。它和"公开仓库"共用一个物理父目录时，隔离必须多套并行：

1. **`.gitignore` 忽略整个记忆层**——公开仓库从源头不含记忆内容
2. **`pre-commit` 钩子守卫**——任何触碰记忆层的提交一律拒绝（防 `git add -f` 与未来误配置）。守卫插在钩子**顶部**，钩子不在版本库内，换机器需手工恢复——这份清单本身就是文档化的
3. **结构占位**——私有目录在公开仓以"空文件夹 + `.gitkeep`"显形：公开仓能看到结构、看不到内容
4. **发布面白名单**——"不入库"（不进源码）与"不发布"（不渲染页面）是两个面，各有一份机器校验的清单
5. **含真实路径 / 项目名的派生文件只留本地**，所在 git 仓用 `.git/info/exclude` 而不是 `.gitignore` 忽略——提交 `.gitignore` 这个动作本身就会把敏感文件名披露给远端

## 七、读取成本是一等公民

AI 体系里，"让 AI 读什么"直接决定每次会话的成本与质量。本体系的所有文档设计都服务于此：

- 规则拆成"目录页 + 分节文件"，**按操作映射**——整读 3.5K tokens 且 77~90% 与当前操作无关的规则文件，拆完每次只读对应分节
- "读取范围必须在读取前可见"：文件名即范围声明（`写入与禁止.md` / `收尾与维护.md`），钩子里写清"什么操作读哪个文件"
- 开场三件套有体量上限，超标进待瘦身清单
